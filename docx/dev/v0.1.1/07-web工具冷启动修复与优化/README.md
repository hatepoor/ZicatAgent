# 07 · Web 工具冷启动修复与优化

> 日期:2026-10-28 · 状态:冷启动修复已完成并实测保留;优化路线 O1~O10 待排期
> 涉及:`tools/browser/__init__.py`、`TMWebDriver.py`、`assets/tmwd_cdp_bridge/`、`simphtml.py`

## TL;DR

`web_scan` "没通"的三层根因:**用户默认浏览器(Edge)未装扩展**(90s 观察始终 0 连入)、**等待窗口 14s 过紧**(扩展重连常态 5~6s)、**报错无指引**。已修 4 处(等待 60s/每秒探测/3s 弹浏览器、NO_TAB_HINT 排查指引、`_probe_remote` 假活自愈+socket 泄漏、服务启动失败可见化),带扩展环境 5 次冷启动 5/5 @6.2s(修复前 7.2s),144/144 tests 通过。优化路线图给出 O1~O10 三梯队:常驻 master(首调 6s→亚秒)、扩展快速重连、砍 token(缓存/去 reload/可访问性树)、鉴权、超时治理、原子动作与编号引用。

## 一分钟结论

- **必须装扩展**:`edge://extensions` → 开发人员模式 → 加载解压缩 → 选 `assets\tmwd_cdp_bridge`;装一次永久有效;只支持 Chromium 系。
- **修完的行为**:扩展失联时最多等 60s(每秒探测,3s 弹浏览器兜底),失败报错含三步排查;端口被占/假活 master 自愈。
- **下一步优化**:从 O1+O2+O3(约 2.5h)开始——master 常驻化 + 扩展 0.5s 退避重连 + 砍 token,新会话首调 6s → 亚秒,常规扫描 token 减半;随后 O5 鉴权(0.5h)。
