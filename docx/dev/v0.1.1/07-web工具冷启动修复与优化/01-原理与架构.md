# 01 · Web 工具原理与架构

> 范围:`web_scan` / `web_execute_js` 两个工具的完整工作机制
> 代码:`tools/browser/__init__.py`(工具层)、`TMWebDriver.py`(连接层,项目根目录)、`simphtml.py`(页面简化)、`assets/tmwd_cdp_bridge/`(浏览器端扩展)

## 1. 设计定位

agent **不启动、不模拟**浏览器,而是让用户日常浏览器里的扩展反向连入 agent 进程。所有操作以用户真实身份(登录态/cookie/指纹)发生在真实浏览器里;不模拟鼠标键盘,而是在页面内注入 JavaScript 直接操作 DOM。

与同类路线的对比:

| 路线 | 代表 | 登录态 | 说明 |
|---|---|---|---|
| 本项目:扩展反向桥 | — | ✅ 真实 | 扩展只当桥,agent/模型在本机,可接任意后端 |
| 外部受控浏览器 | Playwright/Puppeteer、browser-use 默认模式 | ❌ 全新会话 | 需要时 browser-use 可经 CDP attach 真实 Chrome,但新版 Chrome 禁止默认 profile 使用调试端口 |
| 扩展内多 agent | nanobrowser | ✅ 真实 | agent 焊死在扩展里,模型不可换 |
| 真人模拟(RPA) | computer-use 类 | ✅ | 截图+坐标点击,慢且脆 |

## 2. 三个角色

```
agent 进程                              用户浏览器
┌──────────────────────────┐           ┌────────────────────────────┐
│ TMWebDriver master        │           │ TMWD CDP Bridge 扩展 (MV3)  │
│  · WS 服务器 ws://127.0.0.1:18765    │  · service worker 常驻 attempts │
│  · HTTP 服务器 127.0.0.1:18766      │    chrome.alarms probe ~5s / │
│  · sessions/results/acks 登记       │    keepalive ~24s            │
│  · id 配对命令与结果                │  · 上报 tabs_update →        │
└──────────────────────────┘           │    每个可注入标签页=1 session  │
        ▲                              │  · 收 {id,code,tabId} →      │
        └──────── 命令/结果按 id 配对 ──│    注入 JS 执行 → 回传结果     │
                                       └────────────────────────────┘
```

- **master**(`TMWebDriver.py`):纯被动。构造时探测 18766(`_probe_remote`),有活 master 则本进程降级为 remote 客户端(HTTP `/link` 转发),否则自起 WS+HTTP 双服务。会话类型三种:`ws`(页面内脚本)、`ext_ws`(扩展按标签页上报,本项目主用)、`http`(long-poll,5s 窗口)。
- **扩展**(`assets/tmwd_cdp_bridge`,manifest v3):连入后发 `tabs_update`,把所有 `isScriptable` 的标签页注册为 `ext_ws` session;`background.js` 另带 cookies/CDP(`chrome.debugger`)/tabs 开关/management/contentSettings 等后台命令通道。权限含 `cookies`、`debugger`、`declarativeNetRequest`(剥离页面 CSP 以允许 eval)、`<all_urls>`——等于把浏览器完整交给 agent,这是特性,也是无鉴权风险的来源。
- **simphtml**:`web_scan` 调 `get_html()` 注入脚本抓 DOM,过滤边栏/浮动/脚本垃圾并按 maxlen 截断;`execute_js_rich()` 执行 JS 时附带页面跳转与新开标签页(`newTabs`)监控。

## 3. 两个工具的能力边界

**`web_scan`** — 感知:
- 标签页列表(`tabs_only=true` 省 token)、页面简化 HTML(默认上限 35000 字符,`ctx.get_tool_maxlen` 动态调整)、`text_only` 纯文本模式、`switch_tab_id` 切换活动标签页。

**`web_execute_js`** — 操作(优先工具):
- `script` 参数 / ```javascript 代码块 / 本地 `.js` 文件路径三种脚本来源;
- 页面内任意 JS:点击、填表、滚动、同源 fetch、读 DOM、改页面状态;
- `save_to_file` 把大结果落盘,上下文只留摘要;
- 自动监控页面跳转与新开标签页,`no_monitor` 可关。

**边界**:不模拟真人鼠标轨迹(过不了强验证码);控制不了浏览器自身 UI;只支持 Chromium 系(Edge 可用,Firefox 不行);`chrome://` 等不可注入页面不构成 session。

## 4. 一次调用的完整生命周期(冷路径)

```
agent 首次调 web_scan
  → driver is None → first_init_driver()
      → TMWebDriver() 起服务(或接 remote)
      → 循环探测 get_all_sessions()(现:每秒一次,至多 60s;第 3s 弹默认浏览器)
      → 扩展下一轮 alarm 探测到 WS 端口 → 连入 → tabs_update 注册 session
  → 有 session → simphtml.get_html():execute_js 注入抓取(超时 15s)
  → 简化、截断、json 序列化 → 返回 agent
```

热路径(已连接):跳过等待,单次 `web_scan` 实测约 1~1.2s;execute_js 结果等待为 0.2s 粒度轮询。

**关键时序常数**(优化路线图的靶子):扩展重连常态 5~6s / execute_js 超时 15s / HTTP long-poll 窗口 5s / http 型 session 60s 自动过期 / 断连 session 600s 后清理。

## 5. 已知薄弱点

1. 本地回环**无鉴权**:任何能连 18765 的本地进程可驱动浏览器(详见 04 路线图 O5)。
2. MV3 service worker 随时被 Chrome/Edge 睡掉,重连依赖 alarms(clamp 最小间隔受浏览器版本影响)。
3. 后台标签页 JS 定时器被 Chrome intensive throttling 限制(最低 1 次/分钟),页面内轮询式注入可能 15s 超时。
4. 端口硬编码 18765/18766,多实例/残留进程场景行为脆弱(2026-10-28 已加自愈与明确报错,见 03 修复实施)。
