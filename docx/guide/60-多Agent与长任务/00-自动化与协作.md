## 无人值守：`--reflect` 模式

`agentmain.py:298-342`，一共 45 行，契约是：

```python
# 你的监控脚本要提供：
INTERVAL = 120          # 轮询间隔秒
ONCE = False            # 跑一次就退出
def init(args): ...     # 启动初始化
def check(): ...        # 返回 None / 任务字符串 / '/exit'
def on_done(result): ...# 任务完成后回调
LLM = '模型名'          # 可选，指定用哪个模型
```

外层就是一个 `while True: check() → put_task() → 等结果 → time.sleep(INTERVAL)` 循环，脚本文件 mtime 变了就热重载。

`reflect/scheduler.py` 就是一个 45 行契约的实现：126 行代码做了个"迷你 cron"——

- JSON 任务文件放 `../sche_tasks/`，`repeat` 支持 `once/daily/weekday/weekly/monthly/every_24h`；
- 用 `done/` 目录里的文件名做"上次执行时间"，`_parse_cooldown` 算冷却（daily 的冷却故意设成 20h，防漂移）；
- `max_delay` 6 小时：开机太晚就不补跑过时任务；
- 顺带每 12 小时触发一次 L4 归档。

这就是它的"自动化"全貌：**没有 cron 进程，没有守护服务，就是一个 agent 在轮询一个 Python 函数**。极简，但对个人 Agent 完全够用。

## 定时任务：`sche_tasks/*.json`

`reflect/scheduler.py` 的任务格式（见 `memory/kb/scheduled_task_sop.md`）：

```json
{"schedule": "08:00", "repeat": "daily", "enabled": true,
 "prompt": "……", "max_delay_hours": 6}
```

| 字段 | 说明 |
|---|---|
| `schedule` | `HH:MM` |
| `repeat` | `daily` / `weekday` / `weekly` / `monthly` / `once` / `every_Nh` / `every_Nd` |
| `max_delay_hours` | 超过计划时间多少小时就不再补跑（默认 6） |
| `enabled` | 总开关 |

触发判定（`scheduler.py:62-131`）：`enabled` + 当前时间过点 + 冷却已过（用 `sche_tasks/done/<时间戳>_<id>.md` 的文件名当"上次执行时间"）+ 未超 `max_delay`。触发时会把"报告路径"自动拼进 prompt，任务执行完必须把报告写到该路径，否则下次会被判为没跑过。

轮询间隔是 `INTERVAL = 120` 秒（`scheduler.py:11`）。注意 SOP 里写的是"每 60 秒"，以代码为准。

## 子代理：两种进程级协作

来源 `memory/kb/subagent.md`。两种模式，都是**独立进程**，通过文件通信（`agentmain.py:281-297`）：

| 模式 | 命令 | 适用 |
|---|---|---|
| 纯函数 | `--func prompt.txt --nobg` | 单次任务、并行 map、不需要追问 |
| 持续协作 | `--task 名字 --input "..."` | 需要多轮接力、中途纠偏 |

持续协作的通信文件：`output.txt`（含 `[ROUND END]` 表示本轮完成）→ 主 agent 写 `reply.txt` 续下一轮 → 10 分钟无回复则退出；`_stop` / `_keyinfo` / `_intervene` 分别是"停"、"注入工作记忆"、"追加指令"。

约定：所有 agent 的 `cwd = temp/`，方便共享文件；给子代理的 input 只写「目标 + 约束」，不要写步骤。

## Goal 模式：单 worker 的持续优化

`reflect/goal_mode.py` 是一个 reflect 脚本（`INTERVAL = 5`，跑完立刻再看），状态落 `STATE_FILE`，核心是两种 prompt：

- `CONTINUATION_PROMPT`（`goal_mode.py:26`）：目标没达成，继续下一轮；
- `BUDGET_LIMIT_PROMPT`（`goal_mode.py:55`）：预算耗尽，要求收口并交付。

预算是 `budget_seconds`，**代码默认 1800 秒（30 分钟）**（`goal_mode.py:80`）。SOP 里"建议 ≥3 小时"只是经验值，不是默认值。

## Goal Team：多 worker 协作

来源 `memory/kb/goal_team_sop.md`，是 Goal 模式的多进程版：

1. 起一个 BBS 服务：`python assets/agent_bbs.py --cwd temp/team_<名> --port <PORT> --key <KEY>`；
2. 主 agent 发"第一帖"（目标 / 拆解 / 约束 / 终止条件），然后按时间预算拉起 master 与若干 worker；
3. worker 通过 BBS 领任务、回帖、传文件；`reflect/agent_team_worker.py` 就是"轮询 BBS → 抢单 → 执行"的 worker 实现（`INTERVAL = 60`）。

要点：master 和 worker 都是**与你不同的独立进程**，启动后主 agent 应当向用户报告并结束，而不是自己接着干。

## 检查单：把长任务拆成可勾选项

`memory/kb/checklist_sop.md` 定义检查单格式与执行纪律，`memory/scripts/checklist_helper.py` 提供工具函数；`reflect/checklist_master.py` 负责轮询 BBS 上的检查单帖子，发现有更新就驱动一轮。适合"步骤多、容易漏、需要可审计"的任务。

## 怎么选

| 场景 | 用哪个 |
|---|---|
| 到点执行一次固定任务 | 定时任务（`sche_tasks`） |
| 一个目标反复迭代直到达标 | Goal 模式 |
| 多路并行、互不干扰 | `--func` 批量 |
| 需要多轮交接、中途纠偏 | `--task` |
| 多个模型/进程抢同一批任务 | Goal Team + BBS |
| 步骤多、要防遗漏 | 检查单 |
