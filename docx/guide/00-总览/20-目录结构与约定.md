# 目录结构与文档约定

> 文档索引：[docs/README.md](../README.md)

## 三层分离

这个仓库把内容分成三类，**互不混放**：

| 层 | 位置 | 是什么 | 谁能改 |
|---|---|---|---|
| **代码** | 根目录 `*.py`、`core/`、`engine/`、`memstore/`、`reflect/` | 引擎与模块实现 | 开发者 |
| **运行时数据** | `memory/`、`assets/`、`temp/` | Agent 运行时会读写的提示词、技能、工作区 | 程序与 Agent 自己 |
| **文档** | `docs/` | 对项目的描述与讲解 | 人（开发者） |

判断标准很简单：**会被程序 `open()` 读到的，就不是文档。**

例如 `memory/kb/memory_management_sop.md` 看起来像文档，但 `zicat.py` 会直接读取它注入模型，所以它属于运行时数据，必须留在 `memory/`。同理 `assets/sys_prompt.txt` 是系统提示词，不是说明文档。

```
docs/                 文档（本目录）
├── 00-总览/          项目是什么、架构、目录约定
├── 10-核心循环/      主循环与上下文管理
├── 20-工具系统/      工具实现与浏览器控制
├── 30-记忆系统/      L0-L4 记忆
├── 40-自我进化/      SOP 沉淀机制
├── 50-强执行力/      执行稳定性机制
├── 60-多Agent与长任务/ 子代理、Goal/Team、定时任务
├── 70-二次开发/      裁剪记录与改造路线
├── 80-配置与运行/    模型配置、运行模式
├── 85-引擎迁移/      LangGraph/LangChain 迁移评估与设计
└── 90-附录/          差异清单、文件地图、术语表

agentmain.py          入口：任务队列、system prompt 组装、四种运行模式
agent_types.py        公共类型（StepOutcome / BaseHandler / exhaust）
mykey_loader.py       mykey.py 配置加载
zicat.py                 16 个工具实现（含 memory_*）+ 每轮重锚 prompt
simphtml.py           网页 HTML 简化
TMWebDriver.py        真实浏览器桥
core/                 纯后端逻辑 + CLI 命令分发 + JSONL 协议（--rpc）
engine/               LangGraph 引擎（图/状态/工具适配/检查点/runner）
memstore/             SQLite 记忆库（schema/仓库/工具/导入/校验）
tests/                引擎与迁移单测 + 进程集成（python -m unittest tests.test_engine tests.test_integration）
reflect/              无人值守脚本（scheduler / goal_mode / checklist / worker）
memory/               运行时：L0-L4 记忆与技能库
assets/               运行时：提示词、工具 schema、浏览器扩展
temp/                 运行时：工作区与日志（gitignore）
```

## 命名规则

- 文档文件与目录统一用 `NN-中文名` 前缀，`NN` 以 10 递增：`00-`、`10-`、`20-`……
- 同一目录内按数字顺序阅读；数字也表达层级/依赖关系（基础在前，进阶在后）。
- 一个模块一个目录，目录内只放该模块的文档。
- 跨目录引用用相对路径，保持 `docs/` 内部自洽。

## 新增文档的检查清单

1. 它描述的是哪个模块？放进对应目录。
2. 编号是否接在该目录已有的最大编号之后？
3. 是否与 `memory/` 里的 SOP 重复？SOP 是给 Agent 执行的，文档是给人读的，两者用途不同，不要互相搬。
4. 引用了代码就写 `文件:行号`；引用了其他文档就写相对链接。
5. 在 [docs/README.md](../README.md) 的文档地图里补一行。
