## 它到底是什么

一句话：**ZicatAgent 不是一个"平台"，而是一个"能自己长本事的执行内核"**。

- 内核 = 一个约 130 行的 while 循环（`agent_loop.py`）+ 一个约 590 行的工具处理器（`zicat.py`）+ 一个约 1270 行的模型适配/上下文管理层（`llmcore.py`）。
- 核心依赖只有 5 个：`requests`、`beautifulsoup4`、`bottle`、`simple-websocket-server`、`rich`（`pyproject.toml`）。没有 LangChain、没有向量库、没有工作流引擎。
- 它对外只暴露 **9 个原子工具**（`assets/tools_schema.json`），全部是"操作系统级"原语：跑代码、读写文件、看网页、执行 JS、问人、写两处记忆。
- 它把"能力增长"这件事外包给了**文件系统 + 模型自觉**：新能力 = 新脚本 + 新 SOP 文件；下次靠一张极简索引（L1）让模型"想起"有这个能力。

## 五个真正起作用的机制（后面逐条展开）

| # | 机制 | 一句话解释 | 关键代码 |
|---|---|---|---|
| 1 | **薄循环 + 胖 Session** | 循环不存对话，历史全在模型会话对象里；循环每轮只递一个"增量消息" | `agent_loop.py:103` |
| 2 | **每步重锚（re-anchor）** | 每次工具调用后，把"工作记忆 + 历史骨架 + 当前轮次"重新拼成下一轮的 prompt，而不是靠模型自己记住 | `zicat.py:537-547` |
| 3 | **字符预算的上下文裁剪** | 用 `context_win*3` 的字符阈值做头删 + 标签折叠，把长任务压到约 23K token 稳态 | `llmcore.py:136-160` |
| 4 | **存在性索引替代 RAG** | 常驻只有约 1.4KB 的 L1 文件清单；要用时模型自己 `read`，不建向量库 | `memory/l1_fallback.txt` |
| 5 | **节拍化纪律注入** | 每 15/17/41/175 轮固定注入"重读 SOP / 写检查点 / 汇报"等强制提示，给长任务装"心跳" | `zicat.py:559-565` |

## 数据流全景

```
┌──────────────┐   用户输入（CLI / --task / --func / --reflect）
│   入口层      │
└──────┬───────┘
       │ put_task(query) → queue
┌──────▼───────────────────────────────────────────────┐
│ ZicatAgent (agentmain.py)  单线程任务循环           │
│  · 拼 system prompt = 角色 + 日期 + L0宪法 + L1索引   │
│  · 新建 Handler（继承上一任务的工作记忆 key_info）    │
└──────┬───────────────────────────────────────────────┘
       │ agent_runner_loop(client, sys_prompt, query, handler, tools)
┌──────▼───────────────────────────────────────────────┐
│ agent_loop.py  while turn < 180                       │
│   1. client.chat(messages, tools)  ──► LLM            │
│   2. 解析 tool_calls（原生 function call 或文本协议） │
│   3. handler.dispatch → do_<tool>()                   │
│   4. StepOutcome(next_prompt, should_exit, data)      │
│   5. messages = [ {user: next_prompt, tool_results} ] │
└──────┬───────────────────────────────────────────────┘
       │ 工具执行
┌──────▼───────────────────────────────────────────────┐
│ 9 个原子工具                                          │
│  code_run / file_read / file_write / file_patch       │
│  web_scan / web_execute_js / ask_user                 │
│  update_working_checkpoint / start_long_term_update   │
└──────┬───────────────────────────────────────────────┘
       │ 落到磁盘
┌──────▼───────────────────────────────────────────────┐
│ 文件系统 = 唯一的长期状态                             │
│  temp/          工作区（cwd）                         │
│  memory/        L0-L4 记忆与 SOP                      │
│  temp/model_responses/  原始会话日志（L4 原料）       │
└──────────────────────────────────────────────────────┘
```

**记住这张图**：整套框架里没有数据库、没有向量库、没有消息总线。所有"记忆"都是 `temp/` 和 `memory/` 下的文件，所有"能力"都是这些文件 + 9 个工具的组合。
