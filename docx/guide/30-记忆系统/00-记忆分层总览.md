# 记忆分层总览（SQLite 版）

> 文档索引：[docs/README.md](../README.md)
> 实现细节：[10-实现细节.md](10-实现细节.md) · 迁移设计：[docs/85-引擎迁移/20-记忆存储设计](../85-引擎迁移/20-记忆存储设计.md)

## 一句话

记忆已从"`memory/` 下的一堆文件"迁移为 **SQLite 单库（`memory/memory.db`）+ 7 个 `memory_*` 工具**：
写入走版本表（只追加）、读取走工具与动态 L1 索引、文件只保留"L0 宪法、运行时资产、导出快照、备份"四类角色。

## 当前分层

| 层 | 落在哪 | 谁写 | 何时进 prompt / 如何读 |
|---|---|---|---|
| **L0-a 宪法** | `assets/sys_prompt.txt`、`assets/l1_structure.txt` 的 `[CONSTITUTION]` | 开发者（模型改不到） | 每任务 system prompt |
| **L0-b META-SOP** | `memory/kb/memory_management_sop.md`（文件；库里有同名 L3 副本） | 开发者/模型经 sync | 调用 `start_long_term_update` 时由代码读全文 |
| **L1 索引** | **动态渲染**（`memory_items` 查询 + `l1_rules` 规则块） | 代码渲染；模型只能 `memory_patch("l1_rules")` | 每任务注入一次（`render_l1` 记 `inject` 事件） |
| **L2 事实** | `memory_items`（layer=L2, kind=fact） | 模型 `memory_write` / `memory_patch` | 不自动注入；`memory_search` / `memory_read` |
| **L3 能力** | `memory_items`（layer=L3, kind=sop/script） | 模型 `memory_write` / `memory_patch` | 不自动注入；名字出现在 L1 |
| **L4 归档** | `memory_items` 里只存"档案卡"；原始文本仍在 `memory/L4_raw_sessions/` | 代码（`compress_session.py`，12h） | 不注入；`memory_search` 可查摘要 |

> 记忆库文件 `memory/memory.db` 不进 git（`.gitignore`）；可读快照在 `memory/export/`（进 git），
> 二进制快照在 `memory/backup/snapshots/`（不进 git）。

## 目录布局

| 路径 | 内容 |
|---|---|
| `memory/kb/*.md` | 所有 SOP / 原则类 Markdown（含 `index.md` 索引） |
| `memory/facts.txt` | L2 事实文件（兜底/同步源） |
| `memory/l1_fallback.txt` | L1 兜底文本（正常从库动态渲染） |
| `assets/（review prompt）` | `/review` 内联 prompt |
| `memory/L4_raw_sessions/` | L4 原始归档与压缩脚本 |
| `memory/export/`、`memory/backup/` | 可进 git 的导出快照 / 二进制备份 |
| `memory/*.py` | L3 技能脚本 |

## 常驻 prompt 里到底有什么

```python
# agentmain.get_system_prompt()
prompt = assets/sys_prompt.txt              # 角色 + 行动原则
prompt += "\nToday: ...\n"
prompt += zicat.get_global_memory()            # 见下
```

`zicat.get_global_memory()` 注入：

1. `cwd` 与 `[Memory]` 段头；
2. `assets/l1_structure.txt`（层级契约 + 5 条宪法）；
3. **L1**：`zicat.load_L1()` 优先 `MemoryTools().store.render_l1(log=True)`，库不可用才回退 `memory/l1_fallback.txt`。

L1 渲染内容 = 固定 RULES 块（`l1_rules` 条目）+ 由 `memory_items` 生成的 `[SKILL]/[FACT]` 索引，按行截断到约 2000 字符。

## 写入链路

```
模型 → memory_write / memory_patch / memory_archive（工具）
        └─ MemoryTools.dispatch（memstore/tools.py）
            └─ MemoryStore 事务：
                 insert memory_versions（新版本，只追加）
                 update memory_items（当前指针）
                 insert memory_events（审计）
```

约束（由代码 + SQLite 触发器共同保证）：

- `memory_versions` / `memory_events` **禁止 UPDATE/DELETE**（触发器 `RAISE(ABORT)`）；
- 正文变更必须新增版本，旧版本永久保留；
- 同名条目不能重复创建；名称唯一键是 `(layer, name)`；
- 单条 `body` 上限 256KB；
- `kind=script` 初始 `draft`，验证执行后再上线；
- `memory/` 的 `file_write`/`file_patch` 在 **引擎与 handler 两层都会被拦截**（`zicat._memory_write_blocked` / `ToolRuntime`）。

## 读取与检索

| 需求 | 工具 / 代码 |
|---|---|
| 看有什么 | `memory_index`（动态 L1） |
| 关键词检索 | `memory_search`（FTS5 trigram；不足 3 字回退 LIKE） |
| 读正文 | `memory_read`（返回真实版本号，记 `read` 事件） |
| 关系 | `memory_link` |
| L4 历史 | `memory_search` 查档案卡；原文按 `L4_raw_sessions/` 路径读取 |

检索命中会对条目 `touch`（`access_count += 1` + `read` 事件），因此"哪些条目从没被读过"可查。

## 质量与运维

| 机制 | 命令 / 位置 | 作用 |
|---|---|---|
| 迁移校验 | `python -m memstore.verify` | 逐条正文 sha256 对比、版本/事件/触发器检查 |
| 文件同步 | `python -m memstore.sync` | 改完 `memory/*.md` 后把差异写进库（新版本 + 刷新 manifest） |
| 导出 | `python -m memstore.export` | 确定性 md 快照到 `memory/export/`（可 diff、可进 git） |
| 备份 | `python -m memstore.backup` + scheduler 24h | `VACUUM INTO` 快照 + 轮转；**不删库内行** |
| L4 归档 | `reflect/scheduler.py` 12h | 压缩 `temp/model_responses/` 到 `memory/L4_raw_sessions/` |

## 与迁移前的差异（要点）

| 迁移前 | 现在 |
|---|---|
| L1/L2/L3 全是 `memory/*.md`，靠 `file_patch` 改 | 正文进库、版本化；工具写入 |
| L1 是模型手改的 23 行文本 | 动态渲染，列表自动生成；只有 RULES 可改 |
| 无版本、无审计 | 版本 + 事件表，append-only |
| 无检索（只有"模型自己 ls/read"） | FTS5 + LIKE 检索 |
| `memory/` 被 gitignore，无备份 | 导出 md 进 git + 每日快照 |
| 写坏一次无法回滚 | 旧版本可查（`memory_versions`） |

## 仍然存在的弱点

1. **L0-b 仍从文件读**：`memory_management_sop.md` 由 `zicat.do_start_long_term_update` 直接读盘，库里的副本只用于检索/展示；两边靠 `memstore.sync` 保持一致。
2. **`code_run` 仍可写 `memory/`**：工具层只拦了 `file_write`/`file_patch`，任意脚本副作用无法可靠拦截。
3. **append-only 的代价**：事件与版本永久增长，只能靠备份轮转/重建库控制体积，不能按时间 DELETE。
4. **L1 每 15 轮刷新**：已通过 graph 的轮末钩子恢复；任务开始时仍会注入一次。
5. **FTS 对 1–2 个汉字无效**：trigram 需要 ≥3 字符，短词走 LIKE（全表扫描，条目多时变慢）。
