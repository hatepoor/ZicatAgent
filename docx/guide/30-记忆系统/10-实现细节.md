## 0. 结论速览

| 事实 | 证据 |
|---|---|
| 记忆正文在 `memory/memory.db` 的 `memory_items`，历史在 `memory_versions` | `memstore/schema.sql:15,39` |
| 版本与事件**只追加**，触发器禁止 UPDATE/DELETE | `schema.sql:87-101` |
| 写入唯一入口是 `MemoryStore.create/patch/archive` | `memstore/repository.py:292/327/377` |
| 模型通过 7 个 `memory_*` 工具读写，schema 在 `assets/tools_schema.json`（共 16 个工具） | `memstore/tools.py:23`、`zicat.py:510-516` |
| L1 由库动态渲染，任务开始时注入 | `repository.py:237`、`zicat.py:630` |
| `file_write`/`file_patch` 写 `memory/` 在两个引擎都被拦截 | `zicat.py:298`、`engine/tools.py:35,68` |
| 文件仅剩四类角色：L0 宪法、META-SOP、导出快照、备份 | `assets/`、`memory/export/`、`memory/backup/` |

## 1. 文件地图

```
memstore/
├── schema.sql        建表 + 追加式触发器 + FTS 同步触发器
├── db.py             连接 / PRAGMA / user_version 升级
├── repository.py     唯一读写入口（MemoryStore）
├── tools.py          7 个 memory_* 工具实现（MemoryTools）
├── migrate.py        文件 → 库 一次性导入（P1 已执行）
├── verify.py         sha256/版本/触发器校验
├── sync.py           文件改动 → 库（patch + manifest）
├── export.py         库 → 确定性 md 快照（进 git）
├── backup.py         VACUUM INTO 快照 + 轮转
└── materialize.py    L3 script → temp/skills/<name>-<hash>.py
```

接线点：

| 位置 | 作用 |
|---|---|
| `zicat.py:630 load_L1()` | L1 优先从库渲染，失败回退 `memory/l1_fallback.txt` |
| `zicat.py:644 get_global_memory()` | 把 L0 结构 + L1 拼进 system prompt |
| `zicat.py:510-516 do_memory_*` | 转发到 `MemoryTools.dispatch`（legacy 引擎也能用） |
| `engine/runner.py:64 _build()` | graph 引擎的 runtime；`base_prompt` 直接使用已含 L1 的 system prompt |
| `core/commands.py:222 /memory` | CLI 查看索引/检索 |
| `reflect/scheduler.py:78` | 每 24h 备份；12h L4 归档 |

## 2. 表与约束

| 表/对象 | 作用 | 关键点 |
|---|---|---|
| `memory_items` | 当前有效条目（指针） | `UNIQUE(layer,name)`；`status/priority/verified/access_count`；`meta` JSON |
| `memory_versions` | 正文版本（append-only） | 每次 create/patch/archive 插一行 |
| `memory_events` | 事件（append-only） | create/read/patch/archive/inject/materialize |
| `memory_links` | 条目关系 | indexes / supersedes / depends / related |
| `memory_fts` | FTS5 全文索引 | `tokenize='trigram'`，由触发器与 items 同步 |
| `session_state` | 预留：会话工作记忆持久化 | 当前 graph 引擎把 working 放在图状态里，此表未启用 |
| `schema_meta` | schema 版本 | `user_version` 同步 |

追加式由 SQLite 触发器强制：

```sql
CREATE TRIGGER trg_versions_no_update BEFORE UPDATE ON memory_versions
BEGIN SELECT RAISE(ABORT, 'memory_versions is append-only'); END;
-- events 同理；items 允许更新（当前指针）
```

## 3. 写入路径（唯一入口）

```
模型
 └─ memory_write / memory_patch / memory_archive（工具）
     └─ memstore.tools.MemoryTools.dispatch
         └─ MemoryStore.create / patch / archive
             └─ 事务：insert memory_versions → update memory_items → insert memory_events
```

关键实现（`repository.py`）：

- `create`（:292）：校验 layer/kind/status/name/body 上限 → `BEGIN IMMEDIATE` → 查重 → 插 items + versions + events；
- `patch`（:327）：`dataclasses.replace` 拷贝当前条目 → 改字段 → 插新版本 → 更新指针 → 事件；
- `archive`（:377）：等价于 `patch(status='archived')`；
- 事务封装在 `tx()`：`BEGIN IMMEDIATE` / `COMMIT` / 异常 `ROLLBACK`，并由 `Database.lock` 串行化单写者。

写入约束：

| 约束 | 位置 |
|---|---|
| layer ∈ L1–L4、kind ∈ index/fact/sop/script/archive/insight | `_validate`（:133） |
| body ≤ 256KB | `_check_body`（:145） |
| 同名同层不可重复 | `UNIQUE(layer,name)` + create 先查重 |
| script 初始 draft | `tools.py`（create 时 status=draft） |

## 4. 读取与检索

| API | 行号 | 行为 |
|---|---|---|
| `search(query, layer, limit)` | :183 | 长度 ≥3 走 FTS5（`MATCH` + `bm25`）；否则/无命中回退 `LIKE` |
| `read(name)` | :215 | 读正文 + `access_count+=1` + `read` 事件 |
| `touch(item_id)` | :228 | 检索命中后的访问留痕（不读正文） |
| `render_l1(max_chars, log)` | :237 | RULES 块 + active L2/L3 索引；按行截断；默认写 `inject` 事件 |
| `version_count` | :272 | 真实版本数（`memory_read` 返回它） |

`render_l1` 的输出形态：

```
# [Global Memory Insight]
记忆检索用 memory_search，读正文用 memory_read

[RULES]                  ← l1_rules 条目正文
...

## 索引                   ← 查询生成
[SKILL] tmwebdriver_sop — ...
[FACT]  global_mem — ...
```

## 5. 工具层与引擎接线

- schema：`assets/tools_schema.json`（16 个），7 个 `memory_*` 与其余工具共用同一份描述；
- 实现：`memstore/tools.py:MemoryTools`，内部按需打开库（不可用时返回 JSON 错误而不是抛异常）；
- `zicat.py:510` 提供 `ZicatAgentHandler.do_memory_*`；`engine/tools.py:ToolRuntime.run_tool` 统一走 `handler.dispatch`，工具结果按既有协议序列化；
- 写保护：
  - `ToolRuntime._touches_memory`（`engine/tools.py:35`）拦截 `file_write/file_patch`；
  - `ZicatAgentHandler._memory_write_blocked`（`zicat.py:298`）在 `do_file_write/do_file_patch` 开头再拦一层；
  - 未被拦截的旁路：`code_run` 里手动写文件（无法通用拦截，属于已知限制）。

## 6. 文件 ↔ 库 的同步与运维

| 命令 | 模块 | 行为 |
|---|---|---|
| `python -m memstore.sync` | `sync.py:19` | 扫 `memory/`，正文有变化就对同名条目 `patch`，刷新 manifest 的 sha256 |
| `python -m memstore.verify` | `verify.py` | 逐条对比库/源文件 sha256、版本存在性、FTS 行数、触发器、L1 渲染 |
| `python -m memstore.export` | `export.py:33` | 确定性 md 快照到 `memory/export/<layer>/<name>.md`（进 git） |
| `python -m memstore.backup` | `backup.py:55` | `VACUUM INTO memory/backup/snapshots/{memory,graph}-YYYYMMDD.db`，保留 7 日 + 4 周 |
| L4 归档 | `memory/memstore/l4_compress.py` | 12h 压缩 `temp/model_responses/` |
| 备份 cron | `reflect/scheduler.py:78` | 24h 静默执行 `run_backup()` |

> 因为 `memory_versions` / `memory_events` 只追加，**备份任务不删库内行**；磁盘增长靠备份轮转、
> 必要时"重建库"来控制（后续工作）。

## 7. L1 注入链路（graph）

```
agentmain.run()
 ├─ get_system_prompt()            # assets/sys_prompt + Today
 │    └─ zicat.get_global_memory()    # structure + load_L1()
 │         └─ load_L1()            # 库 render_l1(log=True)；失败回退文件
 └─ engine.runner.run_graph_task(..., sys_prompt)
      └─ ToolRuntime(base_prompt=sys_prompt)   # 不再重复追加 L1
```

`engine/hooks.build_model_messages` 每轮把 system prompt 作为视图首条消息，并在超预算时折叠视图
（存储层的 messages 不变，见 `docs/10-核心循环`）。

## 8. L3 脚本物化

`memstore/materialize.py:12`：

```python
digest = sha256(item.body)[:16]
target = temp/skills/<name>-<digest>.py
if not target.exists(): 写入 + 记 materialize 事件
```

内容变则路径变，旧缓存不会被误用；`temp/skills/` 可随时删除重建。

## 9. L4 归档

- 原始会话文本仍由 `memory/memstore/l4_compress.py` 压缩落盘（体积大，不入库）；
- 库里只存"档案卡"（layer=L4, kind=archive，正文为空，`meta` 记录路径/摘要）；
- 目前没有自动生成档案卡的 cron（`migrate.py` 支持，但归档侧未接），属于待办。

## 10. 工作记忆 vs 长期记忆

| 类型 | 存储 | 生命周期 |
|---|---|---|
| 长期记忆 | `memory_items` + versions/events | 永久（append-only） |
| 工作记忆 `key_info` | `ZicatState.working` | 任务/会话级 |
| 轮级摘要 | `ZicatState.summaries` | 会话级 |

`session_state` 表是为"跨重启恢复工作记忆"预留的，当前未使用。

## 11. 已知限制 / 未做

1. `code_run` 可绕过写保护直接改 `memory/`（通用拦截不可行）。
2. L0-b `memory_management_sop.md` 仍由代码从文件读取（`do_start_long_term_update`），库副本只用于检索；靠 `memstore.sync` 对齐。
3. L4 档案卡没有自动生成；`L4_raw_sessions/` 只有原始压缩文本。
4. L1 每 15 轮刷新已通过 graph 的轮末钩子恢复；任务开始时仍会注入一次。
5. FTS trigram 对 1–2 个汉字无效，短词走 `LIKE` 全表扫描。
6. 备份没有"从快照恢复"的自动化脚本（需手工 `cp` 回 `memory/memory.db`）。
