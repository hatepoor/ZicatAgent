## 1. 工具是怎么"注册"和调度的

## schema 只是提示词，不是注册表

`assets/tools_schema.json` 是 9 个 function 定义的 JSON 数组（共 5747 字节），无任何 `required` 字段——所有参数都是可选的，参数缺失/类型错误全部由工具函数自己兜。

加载路径（`agentmain.py:18-23`）：

```python
def load_tool_schema(suffix=''):
    TS = open(os.path.join(script_dir, f'assets/tools_schema{suffix}.json'), ...)
    TOOLS_SCHEMA = json.loads(TS if os.name == 'nt' else TS.replace('powershell', 'bash'))
    TOOLS_SCHEMA = [t for t in TOOLS_SCHEMA if t.get('function', {}).get('name') not in BANNED_TOOLS]
```

三个关键事实：

1. **非 Windows 上直接字符串替换** `powershell → bash`（`agentmain.py:21`）——schema 的枚举值在运行时被篡改，`code_run.type` 的 `enum` 从 `["python","powershell"]` 变成 `["python","bash"]`，磁盘文件与实际下发不一致。
2. **`BANNED_TOOLS`**：`--no-user-tools` 时剔除 `ask_user` 和 `start_long_term_update`（`agentmain.py:17`）。这会让 Agent 失去唯一的人类求助通道。
3. **CN schema 的触发条件很窄**：只有 `frontends/model_cmd.py:66` 在运行时切换模型、且模型名含 `glm/minimax/kimi` 时才 `load_tool_schema('_cn')`；`agentmain.py:114` 的 `next_llm()` 调用的是无参 `load_tool_schema()`，**永远回到英文 schema**。`model_cmd.py:64` 注释说"对齐 agentmain.next_llm 的中文 schema 切换"，但 `next_llm` 里根本没有中文切换——注释与代码不符。启动默认也是英文 schema（`agentmain.py:23`），即使 `ZICAT_LANG=zh`。

## dispatch：do_ 前缀反射

`agent_loop.py:16-29`（全部调度逻辑 14 行）：

```python
def dispatch(self, tool_name, args, response, index=0, tool_num=1):
    method_name = f"do_{tool_name}"
    if hasattr(self, method_name):
        args['_index'] = index; args['_tool_num'] = tool_num
        _hook('tool_before', locals())
        ret = yield from try_call_generator(getattr(self, method_name), args, response)
        _hook('tool_after', locals())
        return ret
    elif tool_name == 'bad_json': return StepOutcome(None, next_prompt=args.get('msg', 'bad_json'), should_exit=False)
    else:
        yield f"未知工具: {tool_name}\n"
        return StepOutcome(None, next_prompt=f"未知工具 {tool_name}", should_exit=False)
```

要点：

- **没有白名单**。`hasattr` 意味着模型只要知道方法名，就能调用任何 `do_*`，包括 schema 里故意不公开的 `do_no_tool`（`zicat.py:468`，注释明确说"不要包含在 TOOLS_SCHEMA 里"）。模型可以主动调用 `no_tool` 直接结束任务。
- **参数注入**：`_index`（第几个 tool_call）、`_tool_num`（本轮共几个）。`_tool_num` 后面被用于**并行预算切分**（`zicat.py:293`），`_index` 用于"只有第一个调用生成完整锚点，其余退化成换行"（`zicat.py:328, 375, 391, 422, 442, 458`）。
- **bad_json** 不是异常处理，是文本协议解析失败后的**伪工具**（由 `llmcore.py:1044` 造出 `MockToolCall('bad_json', ...)`）。它返回 `data=None`，所以不会进 `tool_results`（`agent_loop.py:94`）。
- **未知工具**：yield 一条提示给 UI，返回 `next_prompt="未知工具 xxx"`。`agent_loop.py:93` 检测到该前缀就 `client.last_tools = ''`，下一轮强制重发完整工具说明——用"重新贴文档"来纠错。
- `try_call_generator`（`agent_loop.py:11-14`）：若 `do_*` 返回生成器则 `yield from`，于是工具可以边执行边把过程输出到 UI（`[Action]`/`[Status]` 那些行），最终返回值仍是 `StepOutcome`。

## 运行时 schema 会被改写

`llmcore.py:945-954`，`ToolClient.chat` 每次请求前对 schema 做手术：

```python
for t in tools or []:
    f = t.get('function', {})
    if f.get('name') == 'file_write':
        props = f.get('parameters', {}).get('properties', {})
        props.pop('content', None)      # 删掉 content 参数
        f['description'] += '. Content must be placed in <file_content> tags in reply body, not in args'
        break
```

即：**文本协议模型看到的 `file_write` 没有 `content` 参数**，只能把内容放进 `<file_content>` 标签；而原生 tool-calling 模型（`NativeToolClient.chat`，`llmcore.py:1219`）不做这个改写，仍能看到 `content` 参数。同一份 `tools_schema.json`，两条协议下发给模型的工具定义不同。这解释了两个 schema 都可能被读到、但实际行为有分支的现象。

## hook 包裹（已移除）

P5 批次按 D12 移除了 `plugins/`（hooks 事件总线、project mode、Langfuse）。
`agent_loop.py` 里的 `_hook` 现在是 no-op；graph 引擎从未触发 hook。
如果以后需要事件扩展，建议在 `engine/` 的节点或 LangChain callbacks 上实现，而不是恢复旧总线。

## code_run —— 唯一的"万能兜底"

实现分两层：工具层 `do_code_run`（`zicat.py:303-329`）+ 执行器 `code_run`（`zicat.py:16-98`）。

**参数与语义**（`zicat.py:305-316`）：

- `type`：默认 `python`；`code_type` 未显式给且代码以 `ls|cd|pwd|dir|echo|cat|git|pip|npm|curl|ssh` 开头时，**自动改判为 shell**（`zicat.py:310`）。
- 代码来源三选一：`args["code"]` → `args["script"]` → 从 `response.content` 里抠最后一个 ```` ```python ```` 代码块（`_extract_code_block`，`zicat.py:298-301`）。注意 schema 里只有 `script`，`code` 是不公开的别名。
- `timeout>600` 直接拒绝执行（`zicat.py:316`），**不做超时触发删除**——只是把 `result` 换成一句错误说明，不进入 `code_run()`。
- `cwd = normpath(abspath(join(self.cwd, args.get("cwd", './'))))`（`zicat.py:312-313`）。

**执行器细节**：

- python：写入临时文件 `tempfile.NamedTemporaryFile(suffix=".ai.py", delete=False, dir=code_cwd)`，**先注入 `assets/code_run_header.py` 全文**再写用户代码（`zicat.py:25-30`）。这个 header（27 行）把 `subprocess.run/Popen` 猴补成 UTF-8 安全版、给 Popen 加 `CREATE_NO_WINDOW`、并在 `ImportError/AttributeError` 时打印"NO GUESSING! 先探测"的提示（`assets/code_run_header.py:1-27`）——这是"用注入的运行时补丁来纠正模型行为"的典型手法，schema 里完全看不到。
- powershell/bash：不落文件，`[-NoProfile,-NonInteractive,-Command, utf8_prefix+code]` 一条命令（`zicat.py:32-37`）。
- 流式读取：守护线程 `readline` 到 `full_stdout`（`zicat.py:48-55`），主线程 1 秒轮询判超时，超时 `process.kill()` 并追加 `[Timeout Error]`（`zicat.py:68-76`）。
- 返回：`{"status": "success"|"error", "stdout": smart_format(...maxlen), "exit_code": N}`（`zicat.py:89-93`）；异常路径 `{"status":"error","msg":str(e)}`（`:94-96`）；`finally` 删临时文件（`:97-98`）。
- 给 UI 的预览单独截断到 600 字符（`zicat.py:85`），模型看到的是 `maxlen` 版本（`zicat.py:91`）——**UI 与模型看到的内容长度不同**。

**inline_eval 后门**（`zicat.py:317-326`）：`inline_eval=true` 时在**当前 Agent 进程内** `eval/exec`，命名空间里塞了 `handler`、`parent`、`history`。这等于让模型拿到进程内任意对象的引用（可以改 `parent.llmclient`、读 `mykey` 里的 key）。schema 把它标成 `"DO NOT USE except explicitly specified."`（`tools_schema.json:10`），但代码没有任何权限校验。

## file_read —— 返回字符串，不是 dict

`zicat.py:229-267`。行为要点：

- 过滤器式读取：`dropwhile(行号<start)` → `islice(count)`（默认 200，`zicat.py:433`）。
- `keyword` 模式：命中行 + 前 `count//3` 行 + 后若干行（`zicat.py:234-240`）；**未命中会递归回退成从 start 开始读全部内容**（`:241-242`）。
- **逐行截断**：`L_MAX = min(max(100, 256000//realcnt), 8000)`（`:244`）——行数越少，单行允许越长；超长行变 `...[TRUNCATED]`。
- 总行数统计靠再消费最多 5000 行（`:245`），`remaining>=5000` 时显示成 `12345+`。头部 `[FILE] N lines | PARTIAL showing X; assess need for more`（`:249`）。
- `FileNotFoundError` 时做 **difflib 模糊纠错**：扫父目录和最近读过的目录（`_read_dirs`，`:222, 254`），给前 5 个相似文件名和相似度（`:256-266`）。这是一段很少见的"错误信息即导航"设计。
- 工具层包装（`zicat.py:428-446`）：加中文行号说明（`:438`）、截断提示（`:439`）、`maxlen=15000`（`:440`）、读 memory/SOP 时追加"记得 update working memory"（`:444-445`）、`log_memory_access` 统计（`:443` → `zicat.py:158-166`）。
- **`show_linenos` 依赖 schema 默认值**：`_arg(args,'show_linenos',True,bool)`（`zicat.py:435`），模型不传也开。
- **schema 缺参数**：`keyword` 在实现里存在（`zicat.py:434`），但两个 schema 的 `properties` 里都没有 `keyword`；CN 版只在描述里写"支持分页读取或关键字搜索"（`tools_schema_cn.json:14`）。模型看不到这个参数，基本不会用。

## file_patch —— 唯一性替换

`zicat.py:207-220`。流程：`Path.resolve()` → 读全文 → 空 `old_content` 拒绝 → `full_text.count(old_content)`：0 次报 "not found"、>1 次报 "find N matches"（`:214-216`）→ 唯一则 `replace` 一次并以原文件换行风格写回（`_file_newline`，`zicat.py:193-195`，避免 CRLF/LF 混写）。

工具层额外做 **`{{file:path:start:end}}` 引用展开**（`zicat.py:385` → `expand_file_refs` `zicat.py:179-191`），展开失败返回 error dict 而不是抛异常。注意 `expand_file_refs` 的路径基准是 `base_dir=self.cwd`，但 `{{file:...}}` 里的路径可以是绝对路径或 `../..`——**引用展开没有沙箱**。

## file_write —— 内容不在参数里

`zicat.py:394-426`。schema 描述"HUGE edits ONLY"（`tools_schema.json:31`），实际逻辑相反地**鼓励小块写**：

- 内容来源优先级：`args['content']`（仅原生协议模型可见）→ 回复正文 `<file_content>` 标签 → 回复正文最后一个代码块（`extract_robust_content`，`zicat.py:402-407`）。都没有就报错并要求重写（`:410-412`）。
- `mode` 三态：`overwrite`/`append`/`prepend`（`:398, 415-419`）；仍走 `expand_file_refs` 并保持换行风格。
- **超过 5000 字符就追加系统提示**：`"[SYSTEM TIPS] WRITE TOO LONG! MUST RECHECK HALLUCINATIONS! SMALL WRITES OR PATCHES NEXT TIME!"`（`zicat.py:422`）。也就是说 README/schema 的"大文件一次写完"只是入口描述，运行时用提示词反向压制。
- 成功返回 `{"status":"success","writed_bytes":N}`（`:423`）。

## web_scan —— 返回的是 JSON 头 + 围栏 HTML

`do_web_scan`（`zicat.py:338-351`）：

1. `maxlen = _get_tool_maxlen(35000, args, growth_rate=0.5)`（`:345`）。
2. `web_scan()`（`zicat.py:118-147`）取所有 session 当 tab 列表，剔除 `connected_at`/`type`，**url 截到 50 字符**（`:130-132`）；`switch_tab_id` 只是改 `driver.default_session_id`（`:134`）。
3. `importlib.reload(simphtml)` 后调 `get_html(..., cutlist=True, maxchars=maxlen, text_only=...)`（`:143`）——**每次扫描都热重载模块**，为开发期改 JS 服务。
4. `pop("content")` 后拼成 `JSON + "\n```html\n" + content + "\n```"`（`:347-349`），所以模型收到的是一个字符串而不是 dict。
5. `text_only` 时额外二次截断到 `maxlen//3`（`:144`）。

`next_prompt` 固定为 `"\n"`（`:350`）——**web_scan 这一轮不注入工作记忆锚点**（见 §4.4 的副作用）。

## web_execute_js —— 主战场

`do_web_execute_js`（`zicat.py:353-378`）：

- 脚本来源：`script` 参数或回复里的 ```` ```javascript ```` 块（`:355`）。
- **`script` 若指向存在的文件就当脚本文件读入执行**（`:357-359`）——`_get_abs_path` 拼 `self.cwd`，但绝对路径通吃；配合 `save_to_file`（`:364-371`）形成"读任意 JS 文件 / 写任意路径"的能力。
- `no_monitor` 直通 `simphtml.execute_js_rich`（`:175`）。
- `save_to_file`：把 `js_return` 全文写文件，返回给模型的只剩 `smart_format(content, 170)` + "已保存完整内容到 …"（`:364-370`）。
- 返回：`json.dumps(result)` 再 `smart_format(maxlen=8000*mult)`（`:376-378`）。`smart_format` 是**保头保尾、掐中间**（`zicat.py:269-272`），所以超长返回会是"开头 + `[omitted long content]` + 结尾"。
- UI 侧另有一份 `smart_format(..., 300)` 预览（`:372-373`）。

## update_working_checkpoint —— 短期便签

`zicat.py:452-461`。就三件事：存 `key_info`、`passed_sessions` 归零、第 1 轮追加"别重复调"提示。**没有长度校验**（schema 说 `<200 tokens`，代码原样存），靠 `_get_anchor_prompt` 每轮回灌。

`_get_anchor_prompt`（`zicat.py:537-547`）是它的另一半：

```python
if len(h) > W and self.current_turn % 4 == 1: earlier = '<earlier_context>...'   # W=30
if self.current_turn % 2 == 1: history = '<history>...'                          # 隔轮注入
prompt = "\n### [WORKING MEMORY]\n{earlier}{history}"
prompt += f"\nCurrent turn: {self.current_turn}\n"
if key_info: prompt += f"\n<key_info>{key_info}</key_info>"
```

即：`history`（最近 30 条 80 字摘要）**隔轮**注入，`earlier_context`（更早历史的折叠）每 4 轮注入一次，`key_info` 每轮都注入。**schema 描述"auto-injected each turn"（`tools_schema.json:56`）只在调用者返回该锚点时成立**。

## ask_user —— 用 should_exit 模拟"阻塞"

`zicat.py:331-336`：yield 一行 `Waiting for your answer ...`，返回 `StepOutcome(result, next_prompt="", should_exit=True)`。`agent_loop.py:89-92` 看到 `should_exit` 就 `break` 并把 data 放进 `exit_reason`，**本轮不写 tool_results**。真正的"发问/收答案"由前端完成（`agentmain.py:215` 把 done 推给 queue）。所以工具层没有"阻塞等待"语义，只有"提前结束这一轮"。

## start_long_term_update —— 记忆结算

`zicat.py:509-521`：

- 返回 L0 `memory/memory_management_sop.md` 全文（`:516-517`），L1 超过 6000 字符时追加告警（`:519`）。
- **turn<10 直接降级**：`result='start_long_term_update is only used after completing a long turn task!'`、`next_prompt='\n'`（`:520`）。

## 乘法器从哪来

`zicat.py:291-293`：


`maxlen_multiplier` 在 `BaseSession.__init__`（`llmcore.py:673-678`）：

所以"按模型动态缩放"的真实含义是：**按 `mykey.py` 里配置的 `context_win` 缩放**，模型名只影响分母（deepseek 用 80000，其它 38000）。上限硬顶 3.0，下限 1.0。

| `context_win` | 分母 | multiplier |
|---|---|---|
| 38000（默认） | 38000 | 0.75 → **1.0**（下限抬回） |
| 80000（deepseek 默认） | 80000 | 0.75 → **1.0** |
| 128000（非 deepseek） | 38000 | 2.53 |
| 128000（deepseek） | 80000 | 1.20 |
| 200000（非 deepseek） | 38000 | 3.95 → **截断 3.0** |

注意：同样是 128K 窗口，deepseek 模型因为分母是 80000，拿到的预算只有非 deepseek 模型的一半左右——这个"按模型名改分母"的硬编码会让实际预算依赖模型厂商字符串（`llmcore.py:674`）。

```python
def smart_format(data, max_str_len=100, omit_str=' ... '):
```

## 4. 双通道：`next_prompt` 与 `tool_results`

## 数据结构的定义

`agent_loop.py:6-10`：

```python
@dataclass
class StepOutcome:
    data: Any
    next_prompt: Optional[str] = None
    should_exit: bool = False
```

`data` = 回灌给模型的**工具结果**；`next_prompt` = 下一轮 user 消息里的**指令/锚点**；`should_exit` = 本轮立刻终止。

## 循环里的落地（`agent_loop.py:73-103`）

```python
tool_results = []; next_prompts = set(); exit_reason = {}
for ii, tc in enumerate(tool_calls):
    ...
    outcome = (yield from gen) if verbose else exhaust(gen)
    if outcome.should_exit:
        exit_reason = {'result': 'EXITED', 'data': outcome.data}; break     # (1)
    if not outcome.next_prompt:
        exit_reason = {'result': 'CURRENT_TASK_DONE', 'data': outcome.data}; break  # (2)
    if outcome.next_prompt.startswith('未知工具'): client.last_tools = ''
    if outcome.data is not None and tool_name != 'no_tool':
        datastr = json.dumps(...) if dict/list else str(outcome.data)
        tool_results.append({'tool_use_id': tid, 'content': datastr})        # (3)
    next_prompts.add(outcome.next_prompt)                                    # (4)
next_prompt = handler.turn_end_callback(..., '\n'.join(next_prompts), exit_reason)
messages = [{"role": "user", "content": next_prompt, "tool_results": tool_results}]   # (5)
```

关键点：

- (1)(2) 是**两条不同的终止路径**：`ask_user` 走 `should_exit`（EXITED），`no_tool` 走"空 next_prompt"（CURRENT_TASK_DONE）。所以"空字符串"被复用成控制信号——任何工具只要返回 `next_prompt=""` 就等价于"我干完了"。
- (3) **`data is None` 的工具不会产生 tool_result**（`bad_json`、未知工具），这两类由原生客户端的"补齐空 tool_result"逻辑兜住（见 4.3）。
- (4) 是 `set`——**多个工具的输出会被去重且顺序不确定**。多数工具在 `_index>0` 时返回 `"\n"`（`zicat.py:328` 等），所以实际通常是"第一条的完整锚点 + 一个换行"。
- (5) 每轮**只有一条新 user 消息**，历史在 `llmclient.backend.history` 里（`agentmain.py:195` 的注释明确说明这一点）。

## 两条协议下如何"落地"

**(a) 文本协议 `ToolClient`（`llmcore.py:993-1008`）**：把 `tool_results` 压平成一串标签文本，放在 user 内容之前：

```python
for m in history_msgs:
    user += f"=== {role} ===\n"
    for tr in m.get('tool_results', []): user += f'<tool_result>{tr["content"]}</tool_result>\n'
    user += str(m['content']) + "\n"
```

即：`tool_results` → `<tool_result>` 标签，`next_prompt` → 紧跟其后的正文。模型靠 `<tool_use>` 文本块发起调用（`_parse_mixed_response`，`llmcore.py:1010-1045`）。

**(b) 原生协议 `NativeToolClient`（`llmcore.py:1219-1253`）**：

```python
if msg['role'] == 'user' and msg.get('tool_results'): tool_results.extend(msg['tool_results'])
for tr in tool_results:
    if tool_use_id: tool_result_blocks.append({"type":"tool_result","tool_use_id":tool_use_id,"content":...})
    else: combined_content = [{"type":"text","text":f"<tool_result>{content}</tool_result>"}] + combined_content
for tid in self._pending_tool_ids:                 # 没有结果的 tool_use 补空
    if tid not in tr_id_set: tool_result_blocks.append({"type":"tool_result","tool_use_id":tid,"content":""})
final_content = tool_result_blocks + filtered_content   # tool_result 块在前，文本在后
```

即：有 id 的走结构化 `tool_result` block（API 契约），无 id 的降级成文本块；**上一轮调了工具但没产结果的 id 会被补一个空 `tool_result`**，否则 Anthropic/OpenAI 会 400。

## 为什么要两套（不是冗余）

1. **API 契约不同**。原生 tool calling 要求 `tool_result` 必须与某个 `tool_use_id` 配对、且位于 user 消息的 content blocks 中；而 `next_prompt`（`### [WORKING MEMORY]`、`[TIPS]`、`[DANGER]`）必须是普通 user 文本。合并成一条就必然违约。
2. **控制流与载荷解耦**。`agent_loop.py:91-92` 用 `next_prompt` 的真假判定任务是否结束，`data` 完全不参与控制。`do_ask_user` 用 `should_exit` 而不是 data 表达"要人"，`do_no_tool` 用 `next_prompt=None` 表达"说完了"——这些都是"结果之外"的语义。
3. **截断策略不同**。工具结果按 §3.2 预算截断（掐中间），指令必须语义完整、不能截断（`[DANGER]` 被切一半就废了）。两种数据放在同一字段就没法用两种截断策略。
4. **并发映射不同**。N 个 tool_call 需要 N 条独立 `tool_result`（按 id 精确配对），但**指令只需要一条**（`next_prompts` 是 set，去重后 join，`agent_loop.py:73, 97, 101`）。一条通道无法同时表达 1:N 和 N:1。
5. **协议无关性**。同一份 handler（`zicat.py`）要同时服务文本协议和原生协议；双通道让"压平成标签"（`llmcore.py:1003`）和"升格成 block"（`:1231-1243`）都发生在**客户端层**，工具作者不需要知道协议。

## 双通道的坑（真实存在）

- **`next_prompts` 是 set**：多个工具返回不同锚点时顺序不保证；若有工具返回纯 `"\n"`，join 结果会出现空行抖动。
- **`tool_results` 与 `next_prompt` 的时序**：`next_prompt` 在 `turn_end_callback` 里被追加 summary 提示/危险提示/`[MASTER]` 干预（`zicat.py:549-573`），然后才和 tool_results 一起成消息——所以工具返回后模型看到的"第一条指令"其实被改写过。
- **任务终止时 `tool_results` 直接丢弃**：`should_exit`/空 next_prompt 分支 `break` 发生在 append 之前（`agent_loop.py:89-92` 早于 `:94-96`），`ask_user` 的问题对象只能通过 `exit_reason` 交给前端，不进历史。
- **原生协议下 `json.loads(tc.function.arguments)` 没有 try**（`agent_loop.py:70`）：模型返回的 arguments 不是合法 JSON 时直接抛异常，穿透 `agent_runner_loop` 到 `agentmain.py:217` 的 except，整个任务以 `Backend Error` 结束。文本协议有 `bad_json` 兜底，原生协议没有——这是两套协议健壮性不对等。

## ② 浏览器内主块识别 `js_optHTML`（`:4-327`）

这是"省 token 又不丢关键元素"的核心，思想是**用几何而不是语义判断重要性**：

2. **透明容器合并**（`:77-102`）：若父元素背景透明，就用子元素的并集 rect 代替父 rect（`:85-97`）；否则取最大可见子元素（`:99-101`）。
3. **递归标记 `analyzeNode`**（`:143-185`）：

4. **最后清理**（`:305-325`）：`R:*` 全删（`:306`）；单链容器穿透到真正根（`:308-310`）；三轮空 div 清理（`:311-313`）；**`data-mark` 属性全部移除**（`:314-315`，不留调试痕迹）；有内容的 iframe 转成 `<div data-tag="iframe">`（`:316-324`，之后 Python 侧再改回 `iframe` 标签，`:710-711`）。

1. **只砍"肥"列表**：`avg_len < 200` 的列表（比如导航条、标签）本来就不贵，砍了没收益还丢信息（`:725`）。
2. **保留 3 条**，样本 + 计数 + 前 5 条文本摘要，模型仍知道"这是一个 37 项的列表"，需要更多时可以用 `web_execute_js` 精确取。
3. **`instruction` 参数永远是空**：`get_html` 有 `instruction=""` 形参（`:705`），但 `zicat.py:143` 调 `get_html` 时**从不传**（全仓只有定义处出现，grep 确认）。所以 `:726-727` 的"命中优先保留 6 条"是**死分支**，实际永远保留前 3 条。
4. 注意 `:721` 的 `len(items) < 5: continue` 和 `:725` 的阈值——UI 提示"已隐藏 N 条"是有损压缩，模型如果只读简化结果会**看不到第 4 项以后的内容**，这是 simphtml 的**已知有损边界**（SOP 里也写了"如需查看被过滤的内容请用 execute_js"，`zicat.py:340`）。

## ⑤ 预算截断 `smart_truncate`（`:744-818`）

思路是**递归分摊预算**，而不是简单砍尾：

- `total <= budget` 直接返回（`:771`）。
- 单子元素 → 把预算原样传给子元素继续递归（`:778-782`）。
- 多子元素 → 算超出量 `over`；取最大 3 个子元素按体积比例分摊 `over`（`:786-817`）；若 top3 总量还不够 `over`，**从尾部整块删子元素**（`:790-797`）。
- 真正的"砍"在 `cut`（`:749-769`）：保护 `[FAKE ELEMENT]` 提示标签（`:755`）→ 计算标签开销 → `ele.clear()` → 用 `BeautifulSoup(inner[:inner_keep])` 回填前段 HTML → 追加 `[TRUNCATED Nk chars]` 标记。**截断发生在标签中间，靠 BS4 重新解析修复**，所以可能丢掉最后一个不完整元素——但不会抛异常。
- `CUT_THRESHOLD=8000`：超过 8000 字符才继续递归找分叉点，否则一次性砍（`:747, 816`）。

## 为什么这样能省 token 又不丢关键元素

- **省在**：`svg`/`style`/`data-*`/长 url 全删；浮层/广告/被遮盖元素整棵删；长列表只留 3 项；最后按字符预算递归截断。任何一条都能砍掉 50%+ 字符。
- **不丢在**：判据是"几何可见性 + 交互性 + 文本密度"，不是"标签黑名单"——一个没见过的自定义组件，只要它在视口里够大、含输入框或文本，就会被标成 main/secondary 保留。**不看 class 名字判断内容**（只有 layout 分类时参考 nav/breadcrumbs）。
- **留后路**：被裁掉的东西保留"选择器 + 数量 + 前 5 条摘要"的 `[FAKE ELEMENT]` 提示，模型可以用 `web_execute_js` 按 selector 精确取回。
- **副作用**：简化结果**不是有效 HTML**（`R:*` 删了、属性删了、可能截断在标签中间），只适合给模型读，不适合回填 DOM。`get_html` 明确是"观测视图"，不是"可编辑文档"。

## `execute_js_rich`：执行 + 变更监控（`:820-873`）

1. `no_monitor=False` 时先抓一份 baseline：`get_html(..., extra_js=temp_monitor_js, maxchars=9999999)`（`:822-824`）——同时注入文本监控器 `startStrMonitor(450ms)`（`simphtml.py:622-635`），记录页面上出现过的文本片段，用来捕获 toast/一闪而过的提示。
2. 执行 JS（`driver.execute_js`），`response['data']` → `js_return`；`closed==1` → `reloaded`（`:829-832`）。
3. 返回骨架 `{status, js_return, tab_id}`（`:838-842`），再补 `reloaded`/`newTabs`/`error`（`:843-852`）。
4. 未刷新且有新 tab 时不发 diff，直接给 `suggestion`（`:845-851`）。
5. 未刷新时：取 `transients`（`get_temp_texts` `:640-660`）+ 重新抓 HTML，用 `find_changed_elements` 做**结构化 diff**（`:672-703`）——按 `tag:attrs:直接文本` 生成签名，签名新增或数量变多即视为变化，取变化元素中"父不在变化集"的最大子树作为 `top_change`（截断 2000 字符）。
6. 结果塞进 `rr['diff'] = "DOM变化量: N\n最显著变化:\n..."`（`:864-872`）。

**这是"每步操作后自动回灌变化摘要"的机制**——模型不必每步 `web_scan`，靠 diff 就能确认动作是否生效（省 token 的关键设计之一）。

**坑（代码级）**：

- `get_html` 在 `text_only=True` 时第 706 行的 `findMainList` 仍会执行，但结果 `rr` 在 `:708` 直接 return 后不用——纯浪费一次 JS 往返。
- `execute_js_rich` 里 `time.sleep(1)` 固定等 1 秒（`:832`），SPA 慢页面仍然偏乐观。
- 监控模式一共要抓 2~3 次全量 HTML（baseline / 变更 / 无 baseline 时抛异常），在超大页面上本身就贵；`no_monitor=True` 就是为这个准备的逃跑按钮。

## 6. TMWebDriver：真实浏览器控制面

## 组件拓扑

```
┌──────────────────────── Python 进程（Agent） ────────────────────────┐
│  zicat.py: driver = TMWebDriver()          # 全局单例（zicat.py:107-116）    │
│  WebSocketServer(127.0.0.1:18765)  ←── 扩展长连                       │
│  bottle HTTP(127.0.0.1:18766)      ←── 浏览器 long-poll 兜底 / 远程代理 │

                │ WS: {id, code, tabId} →  {type:ack|result|error, id}
┌───────────────┴──────── Chrome（用户真实 profile） ──────────────────┐
│ assets/tmwd_cdp_bridge  (MV3 扩展)                                    │
│   background.js: WS 客户端 + 命令路由 + chrome.debugger(CDP)           │
```

代码证据：`TMWebDriver.py:41-51`（端口 18765，`port+1` 做存活探测与远程模式）、`:53-116`（HTTP server + `/api/longpoll` `/api/result` `/link`）、`:125-167`（WS server）、`:188-248`（执行）、`assets/tmwd_cdp_bridge/background.js:216`（`WS_URL='ws://127.0.0.1:18765'`）。

## 消息协议

| 方向 | 消息 | 处理 |
|---|---|---|
| 扩展 → Python | `{type:'ready'}` | 单 tab 注册（`TMWebDriver.py:131-135`），type=`ws` |
| 扩展 → Python | `{type:'ext_ready'\|'tabs_update', tabs:[{id,url,title}]}` | 每个 tab 注册成 Session，id = **Chrome tabId**，type=`ext_ws`；消失的 tab 标记断连（`:136-149`） |
| 扩展 → Python | `{type:'ack', id}` | 标记脚本已送达（`:150`），用于区分"没送到"和"送到了没跑完"（`:227-228`） |
| 扩展 → Python | `{type:'result'\|'error', id, result, newTabs}` | 写 `self.results[id]`（`:151-154`，HTTP 侧 `:82-89`） |
| Python → 扩展 | `{id: uuid, code, tabId}` | `execute_js` 组装（`:213-216`） |
| Python → 扩展（CDP 桥） | `code` 是 JSON 字符串 `{"cmd":"cdp"\|"cookies"\|"tabs"\|"batch"\|"management"\|"contentSettings"}` | background.js 先 `JSON.parse(code)`，识别到 `cmd` 就路由到 `handleExtMessage`（`:364-391`） |

有意思的是 **CDP 桥没有独立通道**：它把"命令对象"当作"要执行的 JS 代码"塞进同一条 WS 消息，靠扩展侧 `JSON.parse` 成功与否来分流。SOP 里 `web_execute_js script='{"cmd":"tabs"}'` 的用法就来自这里（`memory/tmwebdriver_sop.md:46-56`）。

## Session / tab 生命周期

- `Session`（`:11-37`）：`type ∈ {ws, http, ext_ws}`，`is_active()` 对 http 类型有 60 秒自动断连（`:22-24`），`reconnect()` 复用 id（`:25-34`）。
- 新 tab：`latest_session_id` 更新；**`default_session_id` 只在为 None 时赋值**（`:181-182`），所以第一个连上的 tab 会长期占据默认位，直到 `switch_tab_id` 显式改写（`zicat.py:134, 174`）。
- 目标 session 掉线：`execute_js` 会睡 3 秒重查，仍不可用则**自动切到任意一个活着的 session**（`TMWebDriver.py:197-208`）——便利但危险：可能在错误的 tab 上执行操作。
- 导航检测：执行中若 session 断开又重连，返回 `{'result': "Session x reloaded.", 'closed': 1}`（`:229-235`）；`execute_js_rich` 据此把 `reloaded` 标记回灌（`simphtml.py:831, 843`），这正好对应 SOP 的坑"导航和后续操作必须拆成两次调用"（`memory/tmwebdriver_sop.md:20`）。
- 超时三级文案（`:233-240`）：`reloaded` / `ACK received, script may still be running` / `no ACK, script may not have been delivered`——把"事实"而不是"异常"返回给模型。
- 清理：`clean_sessions` 删除断开 >600 秒的 session（`:118-123`），每次 `execute_js` 调用一次（`:222`）。

## 脚本执行的两条路径（扩展侧）

`background.js:268-338` `handleWsExec`：

1. 先 `ack`（`:271`）。
2. `chrome.scripting.executeScript({target:{tabId}, world:'MAIN', func: async (s)=>await eval(s), args:[buildPageScript(code)]})`（`:283-289`）——在**页面主世界**执行，能直接碰到页面自己的 JS 变量（jQuery/Vue 实例）、不受 content script 隔离限制。
3. `buildExecScript`（`:157-197`）负责：把返回值做 `smartProcessResult` 序列化（DOM 节点 → `outerHTML`，NodeList → 数组，Window → `'[Window: url]'`，不可序列化 → `'[无法序列化: ...]'`）；`_air` 启发式（`:184`）在最后一行不是 `return/let/if/...` 时**自动补 `return`**——这就是 SOP 说"用 await 时需显式 return"（`memory/tmwebdriver_sop.md:8`）的底层实现：补 return 只对纯表达式安全，`await` 语句末尾会被当成表达式。
4. 返回 `null`/异常且带 CSP 特征 → **降级 CDP**：`chrome.debugger.attach` + `Runtime.evaluate({expression, awaitPromise:true, returnByValue:true})`（`:299-318`）。
5. 新 tab 捕获：执行前挂 `chrome.tabs.onCreated` 监听（`:277-279`），等 200ms 宽限（`:320`），把新 tab 一并回传（`:322-332`）。

另外扩展在安装时用 `declarativeNetRequest` 动态规则**剥掉所有 `content-security-policy` 响应头**（`background.js:5-15`），content.js 再删页面里的 `<meta http-equiv="Content-Security-Policy">`（`content.js:3-4`）——双保险让 `eval` 在严格 CSP 站点也能跑。

## 为什么能保留登录态

因为**根本没有"新浏览器"**：

1. 扩展跑在用户日常 Chrome 里，用的是用户 profile 的 Cookie / localStorage / 已登录 session（`memory/tmwebdriver_sop.md:4-5`："通过 Chrome 扩展接管用户浏览器（保留登录态/Cookie）"）。
2. 没有 `--user-data-dir` 临时目录，没有 `--enable-automation`、没有 `--headless`，不启动任何浏览器二进制（`pyproject.toml:11-17` 依赖里没有 playwright/selenium；全仓 grep 无 playwright/selenium 引用）。
3. 扩展还在 `document_start` + `world: MAIN` 下执行 `disable_dialogs.js`，其中第 2 行：

```js
try{delete Navigator.prototype.webdriver;delete navigator.webdriver}catch(e){}
```

**直接删除 `navigator.webdriver`**——这是 SannySoft/Incolumitas 一类检测最主要的一项。同时把 `alert/confirm/prompt` 换成 toast（`:22-24`），因为原生弹窗会阻塞整个页面的 JS 执行（这也是 Playwright 世界里常见的卡死源）。`confirm` 恒返回 `true`，`prompt` 返回默认值。
4. 扩展还持有 `debugger` 权限，能按需 `chrome.debugger.attach` 发 CDP 命令，但**这个 attach 是"扩展级"的，不是自动化框架的**。

所以 README 第 739 行宣称的"bot.incolumitas 36/36 通过、SannySoft 56/56 通过"在机制上**有解释**（webdriver 已删、无自动化 flag、真实指纹），但**具体分数未在本次分析中复现，标记未验证**。

## 与 Playwright / Selenium 的本质区别

| 维度 | Playwright / Selenium | TMWebDriver |
|---|---|---|
| 谁拥有浏览器 | 框架启动并拥有一个浏览器实例（或连 CDP） | **用户自己的浏览器**，Agent 只是借用手 |
| 登录态 | 需注入 cookie/storage_state，通常新 context | 原生 profile，天然已登录 |
| 自动化 API | 丰富的 locator/auto-wait/network/route/assert | 只有"给我一段 JS + tabId"；同步/等待全靠 Agent 自己 |
| 隔离性 | 每次可控 env、可并行多 context | 全局单例，共享用户真实环境；并行靠多 tab |
| 反检测面 | `navigator.webdriver=true`、CDP 痕迹、自动化 flag 需要专门 stealth 补丁 | 无 webdriver 标志、无自动化 flag；CDP 仅在需要时 attach（`chrome.debugger` 的 infobar 只在 attach 期间出现） |
| 失败模式 | 选择器超时抛异常 | 返回人类可读字符串（`No response data in 15s (ACK received...)`），**status 仍是 success** |
| 能力上限 | 受框架 API 约束 | 受"能不能用 JS 表达"约束；JS 做不到的（真实键鼠事件、文件选择）走 CDP 桥（`background.js:140-152`） |

一句话：Playwright 是"**驱动一个我拥有的浏览器**"，TMWebDriver 是"**在我主人的浏览器里注入一个助手**"。前者 API 更完备但指纹可识别、登录态要搬运；后者指纹真实但抽象弱、需要 Agent 自己写 JS。

## CDP 桥的额外能力

`background.js:18-80` 暴露 6 类命令：`status`、`cookies`（含 partitionKey 合并，`:87-105`）、`tabs`（create/switch/list，`:23-45`）、`cdp`（透传任意 CDP method，`:140-152`）、`batch`（一次请求跑多条，`$N.path` 引用前序结果，`:107-138`）、`management`（扩展 list/reload/disable/enable，`:46-66`）、`contentSettings`（`automaticDownloads` 等，`:67-78`）。
这批命令**不在 9 个 schema 工具里**，模型只能靠 `web_execute_js` 传 JSON 字符串来用——这是"工具层不扩容、能力靠协议"的另一个例证。

## 7. 为什么"9 个工具就够"

## 分工是正交的

9 个工具其实是 4 组：

- **执行原语**：`code_run`（图灵完备，吞掉一切"能用代码表达"的能力）。
- **高频 IO 快通道**：`file_read/file_patch/file_write`——读写改是每一步都要做的事，做成专用工具是为了**免去"先生成脚本再执行"的两次往返**，并附带唯一性校验（`zicat.py:214-216`）、模糊纠错（`zicat.py:256-266`）、换行风格保持（`:193-195`）这些"代码做不到的顺手性"。
- **不可替代的观测/控制**：`web_scan/web_execute_js`——浏览器是有状态、有登录态的**外部进程**，无法用 `code_run` 在子进程里重建，所以必须是一等工具。
- **元工具**：`update_working_checkpoint`（短期记忆）、`start_long_term_update`（长期结算）、`ask_user`（人类通道），加上引擎隐藏的 `no_tool`（终止哨兵）。

## code_run 如何"吞掉"其余能力

仓库自己的做法就是证据：**键鼠、视觉、ADB、OCR 全都不在 schema 里**，而是 `memory/` 下的脚本 + SOP：

| 能力 | 落地物 | 证据 |
|---|---|---|
| Windows 键鼠/窗口/截图 | `memory/ljqCtrl.py`、`macljqCtrl.py` | `memory/computer_use.md:20, 40` |
| UI 元素检测（YOLO+OCR） | `memory/ui_detect.py` | `:1-16`（输出 `bbox/type/label/confidence`） |
| 本地 OCR | `memory/ocr_utils.py` | `:1-8`（含 rapidocr 的坑） |
| VLM 视觉 | `memory/vision_api.template.py` → 复制为 `vision_api.py` | `memory/vision_sop.md:21-25` |
| 安卓 UI | `memory/adb_ui.py`（u2 优先，原生 uiautomator 兜底） | `:1-6, 60-79` |
| 浏览器 CDP | `assets/tmwd_cdp_bridge/` + `web_execute_js` 传 JSON | `memory/tmwebdriver_sop.md:44-56` |

这就是"9 个工具"能覆盖"键鼠/视觉/ADB"的真实机制：**不是工具有这些能力，而是 `code_run` 能 import 这些能力的脚本**。schema 里看不到它们，模型通过读 SOP 才知道去哪儿找（`memory/computer_use.md:3` 就是索引指针）。

## 固化路径（README 的"自我进化"落地版）

README `:668-679` 画的流程，对应到代码是：

```
遇到新任务
  → code_run 装依赖/试脚本（zicat.py:327，临时文件落在 temp/，zicat.py:25）
  → 调试通过后 file_write 把脚本落到 memory/xxx.py（zicat.py:394）
  → file_write 把用法/坑写成 memory/xxx_sop.md（zicat.py:394）
  → update_working_checkpoint / start_long_term_update 记住索引（zicat.py:452 / 509）
  → 下次同类任务：file_read('memory/xxx_sop.md')（zicat.py:428）→ code_run 里直接 import
```

**关键限制**：这条链是"**文本记忆 + 脚本文件**"，不是"**工具注册**"。没有任何代码能往 `TOOLS_SCHEMA` 或 handler 上新增 `do_*`（全仓无 `register_tool`/`append`）。所以 README `:653-655` 的"动态创建新工具"实际应理解为"**动态创建可复用脚本 + 让模型记住怎么调它**"。唯一的"真·运行时改工具"是 `code_run(inline_eval=True)` 在进程内 `setattr`，但那不持久也不安全（见 §9）。

## 为什么工具少反而更准

- 工具说明的总量：`tools_schema.json` 5747 字节（约 1.5K token），且协议层在 schema 未变时压成一句话（`llmcore.py:987-990`），稳态下几乎为 0。
- 选择空间小：9 选 1 的决策成本远低于"几十个专用工具"。`code_run` 作为唯一入口时，模型不需要判断"这个网站该用哪个爬虫工具"，只需要写 JS。
- 代价：**能力发现全靠 SOP**。没有 SOP 就被迫现场摸索；SOP 质量差会直接拉低成功率。这是"最小工具集"的真实代价，README 没有强调。

## 9. 工具层的风险

## 任意代码执行（最高危）

- `code_run` 用**当前用户权限**跑任意 Python/PowerShell（`zicat.py:31, 58-63`），无沙箱、无目录限制、无网络限制。提示词里没有任何"禁止"约束（`assets/sys_prompt.txt` 只谈方法论）。
- `inline_eval=True` **在 Agent 进程内 eval**，命名空间暴露 `handler`/`parent`/`history`（`zicat.py:317-326`）：模型可以改 `parent.llmclient`、读 `mykey` 里的 API key、甚至 monkeypatch `do_*` 方法。schema 只写了"DO NOT USE"，没有技术拦截。
- PowerShell 分支直接 `-Command code`（`zicat.py:36`），`Start-Process`、注册表、计划任务全在射程内。

## 路径逃逸

- `_get_abs_path`（`zicat.py:294-296`）= `abspath(join(self.cwd, path))`，**绝对路径和 `../../` 直接生效**；`file_read/file_write/file_patch` 均可读写进程可访问的任意文件（含 `mykey.py`、`.git/`、系统目录）。
- `code_run` 的 `cwd` 参数同样无校验（`zicat.py:312-313`）。
- `expand_file_refs`（`zicat.py:179-191`）把任意文件的任意行读进来拼到写出的内容里，是现成的**跨文件内容搬运/外泄通道**。
- `web_execute_js` 的 `script` 若是已存在文件路径就读入执行（`zicat.py:357-359`）、`save_to_file` 可写任意路径（`:366-369`）。

## 超时 / 僵死 / 半死状态

- `code_run` 的超时是 **1 秒轮询 + `process.kill()`**（`zicat.py:68-76`）：只能杀直接子进程，**孙进程会成孤儿**（Windows 下尤其明显，没设 JobObject）。`timeout` 上限 600 秒（`zicat.py:316`）。
- 杀掉后 `exit_code = process.poll()` 可能仍是 `None`（`zicat.py:79`），此时 `status = "error"`、`status_icon = "⏳"`——模型会看到矛盾的"失败 + 进行中"。
- `web_execute_js` 的 15 秒超时（`TMWebDriver.execute_js` 默认 `timeout=15`，`TMWebDriver.py:188`）**不抛异常**，返回一句 `No response data in 15s (ACK received...)`，`execute_js_rich` 把它当作 `js_return`、`status` 仍是 `success`（`simphtml.py:830, 838-842`）。**脚本可能还在页面里继续跑**（比如导航），后续操作会撞上"页面已换执行上下文"。
- 迟到结果无人回收：`self.results`/`self.acks` 只在成功路径 `pop`（`TMWebDriver.py:242-243`），超时后到达的结果会永久驻留 → **长跑进程缓慢内存泄漏**。
- 断线自动切 tab（`:202-206`）在错误页面上执行脚本，可能造成不可逆操作。

## 浏览器单点依赖

- `driver` 是模块级全局单例（`zicat.py:107`），首次调用最多等 14 秒（7×2s），第 5 次失败还会**主动 `webbrowser.open('https://example.com')`**（`zicat.py:112-116`）——副作用式自启动。
- 扩展没装/Chrome 没开 → `web_scan`/`web_execute_js` 全部 `{"status":"error"}`，没有降级到 HTTP 抓取或 headless 的路径（`zicat.py:127, 173`）。SOP 里有排查流程（`memory/tmwebdriver_sop.md:131-137`），但那是**给模型看的文档，不是代码兜底**。
- 每次 `web_scan` 都 `importlib.reload(simphtml)`（`zicat.py:143`）——开发期方便，生产期是每次扫描的额外开销，且若有并发调用存在模块重载竞态（未验证）。

## 上下文 / 语义风险

- `smart_format` 掐中间（`zicat.py:269-272`），日志/HTML 的关键错误可能正好在中间被删。
- `next_prompts` 是 `set`（`agent_loop.py:73`），多工具时顺序不确定。
- `update_working_checkpoint` 无长度校验（`zicat.py:454-455`），`key_info` 每轮注入，可被无限撑大。
- 简化后的 HTML 是有损的（cutlist 只留 3 项、`R:*` 整删），模型如果假设"没看到就是没有"会误判页面状态。
- `agent_loop.py:70` 对原生 tool-call 的 `json.loads(arguments)` **无 try**，一个坏 JSON 就让整个任务以 `Backend Error` 结束。

## 可观测性 / 插件

- hook 异常只写 stderr（`hooks.py:23-24`），静默失败；`trigger` 的返回值被调用方丢弃（§1.4），想靠 hook 改写上下文会踩空。
- `log_memory_access` 每次读 memory 文件都**非原子地重写** `memory/file_access_stats.json`（`zicat.py:158-166`），并发下会丢计数/损坏 JSON（未验证实际并发场景）。
- 所有工具的过程输出（`[Action]` 等）走 `yield` 给 UI，不进模型上下文——这是有意的（省 token），但排障时容易误以为模型看到了这些行。

## 10. 复刻 checklist

> 目标：用最小代码复现"9 工具 + 双通道 + 简化 HTML + 真浏览器"这套结构。

### A. 工具层骨架

- [ ] 定义 `StepOutcome{data, next_prompt, should_exit}`（`agent_loop.py:6-10`），**三个字段缺一不可**：data 供证据、next_prompt 供指令+终止、should_exit 供立即退出。
- [ ] `dispatch` 用 `hasattr(f"do_{name}")` 反射；注入 `_index`/`_tool_num`；未知名返回可继续的 prompt 并清空工具缓存（`agent_loop.py:18-29, 93`）。
- [ ] 保持"空 next_prompt = 任务完成"的约定（`agent_loop.py:91-92`），并至少留一条 `should_exit` 路径给 ask_user。
- [ ] 写 schema 时**不写 `required`**，参数容错放到工具内（`_arg` 模式，`zicat.py:197-205`）。
- [ ] schema 与实现之间允许"未公开别名"，但要在文档里登记（否则复刻者会踩 `keyword`/`code`/`tab_id` 的坑）。

### B. 上下文预算

- [ ] `_get_tool_maxlen(base, growth, tool_num)`：`multiplier = 1+(ctx_mult-1)*growth`，再 `/tool_num`（`zicat.py:291-293`）。
- [ ] 乘法器 `min(max(ctx_win/default*0.75,1),3)`，默认窗口 38K / deepseek 80K（`llmcore.py:673-678`）。
- [ ] 每个工具给基线与 growth：读文件 15K/1.0，代码 10K/1.0，JS 8K/1.0，网页扫描 35K/**0.5**（`zicat.py:315, 345, 377, 440`）。
- [ ] 输出截断用"头尾保留 + 中间标记"（`smart_format`），并对长行做 per-line cap（`zicat.py:244`）。
- [ ] 历史侧：按 interval 压缩 `<thinking>/<tool_use>/<tool_result>` 与 `<history>/<key_info>` 标签，超 cap 后从 user 边界丢消息（`llmcore.py:77-109, 136-160`）。
- [ ] 工具 schema 未变时下发一句"工具库持续有效"（`llmcore.py:987-990`），并每 N 轮强制重发一次（`agent_loop.py:56`）。

### C. 双通道回灌

- [ ] 一轮里：N 个工具 → N 条 `{tool_use_id, content}`；指令用 set 去重后 join（`agent_loop.py:94-101`）。
- [ ] 每轮只追加**一条** user 消息，历史留在 session（`agent_loop.py:103`）。
- [ ] 文本协议：`<tool_result>` 标签 + 正文（`llmcore.py:1000-1004`）。
- [ ] 原生协议：`tool_result` blocks 在前、文本在后；**上一轮缺失的 tool_use id 补空 result**（`llmcore.py:1230-1243`）。
- [ ] 给 `json.loads(tool_call.arguments)` 加 try/except，转成 `bad_json`（复刻时必须补，原实现这里是缺口）。

### D. 简化 HTML（simphtml 复刻要点）

- [ ] 在浏览器里做可见性/几何计算，不在 Python 里做（`getBoundingClientRect` + `getComputedStyle`）。
- [ ] 判据：面积、视口占比、z-index、`elementFromPoint` 反查最上层、`aria-hidden`、透明背景父容器合并（`simphtml.py:55-102, 229-274`）。
- [ ] 覆盖 vs 划分二分 + `K:main/secondary/nonEssential`、`R:covered/floatingAd` 标记（`:171-209`）。
- [ ] 特判：小 dropdown 强制保留、同源 iframe 穿透、shadowRoot 展开、fixed 弹窗提升到 body（`:24-27, 34-53, 293-304`）。
- [ ] 属性白名单 + `svg`/`style`/`data-*`/长 url 清零（`:596-619`）。
- [ ] cutlist：`items>=5` 且 `avg_len>=200`（或 `>=700 && total>=2500`）才裁，留 3 条 + `[FAKE ELEMENT] N more items hidden, selector: "..."` + 前 5 条摘要（`:721-738`）。
- [ ] 预算截断：单子元素穿透、top3 按比例分摊、扛不住则尾部整块删、保护提示标签（`:744-818`）。
- [ ] `execute_js_rich` 做"执行 → 等 1s → 重新抓 HTML → 结构化 diff → transients"（`:820-873`），让模型每步少一次全量扫描。

### E. 浏览器控制面

- [ ] Python 起 `WebSocketServer(127.0.0.1:18765)`，扩展作为客户端连入并上报 `ext_ready + tabs`（`TMWebDriver.py:125-167`；`background.js:353-363`）。
- [ ] 协议最小集：`{id, code, tabId}` → `ack`/`result`/`error`；**ack 与 result 分开**，才能区分"没送到"和"没跑完"（`TMWebDriver.py:150-154, 227-240`）。
- [ ] 页面执行用 `chrome.scripting.executeScript(world:'MAIN')` + `eval`；CSP 失败降级 `chrome.debugger` + `Runtime.evaluate`（`background.js:283-318`）。
- [ ] 返回值序列化：Element→outerHTML、NodeList→数组、Window→占位、不可序列化→字符串（`:159-177`）。
- [ ] 导航检测：session 断开又重连 → 返回 `closed:1`，让模型知道"页面换了，重新扫描"（`TMWebDriver.py:229-235`）。
- [ ] 反检测必备：`delete navigator.webdriver`、不传自动化启动参数、用真实 profile、剥 CSP 头/元标签、屏蔽 alert/confirm/prompt（`disable_dialogs.js:2, 22-24`；`background.js:5-15`；`content.js:3-4`）。
- [ ] 支持"命令对象当 JS 传"的旁路（`code` 是 JSON 字符串且含 `cmd` → 走扩展命令路由），这样 CDP/cookies/tabs 不用新增 schema 工具（`background.js:364-391`）。

### F. 扩展能力（SOP + 脚本）

- [ ] 键鼠/视觉/ADB 不进 schema：写 `memory/*.py` + `*_sop.md`，用 `code_run` import（`memory/computer_use.md`, `adb_ui.py`, `ui_detect.py`, `ocr_utils.py`, `vision_api.template.py`）。

### G. 安全兜底（原实现缺，复刻建议补）

- [ ] `inline_eval` 默认禁用或降权（原实现只在 schema 描述里写"别用"）。
