# 进化闭环

> 文档索引：[docs/README.md](../README.md)

经验如何沉淀为 SOP、如何被召回，以及这套机制的真实边界。

---

## "自我进化"的真实闭环

```
[A] 召回：L1 索引每轮都在 system prompt 里（agentmain.py:35-39 → zicat.py:581-591）
      ↓
[B] 触发：任务结束，工具描述"点名"（"超15轮必须调用"）→ do_start_long_term_update
      ↓
[C] 写入：注入 L0 规范全文 → 模型自己 file_write/file_patch 到 memory/
      ↓
[D] 下次：L1 里的自解释文件名被模型看见 → file_read → 提取关键点进工作记忆
```

**关键事实：仓库里没有任何一行代码会"自动生成 SOP"。** 代码只负责"在该沉淀的时候把模型按到桌前"。这是理解"真进化 vs 提示词工程"的分水岭。

## SOP 的格式模板（从上游 37 个 SOP/脚本归纳）

> 下表的例子取自上游语料；其中 `github_contribution_sop`、`ljqCtrl_sop`、`plan_sop` 已随裁剪移除，这里保留作为**格式参考**，不影响模板本身的可用性。当前仓库仍有 21 个能力文件可参照（如 `tmwebdriver_sop.md`、`review_sop.md`、`goal_team_sop.md`）。

| 槽位 | 作用 | 实例 |

| 编号步骤 + 硬门槛 | 步骤可执行、门槛不可跳 | `github_contribution_sop.md:52-61`（`⛔ 测试不过不推代码`） |
| 验证（怎么算成功） | 把"完成"锚到现实证据 | `web_setup_sop.md:22-25` |

一个很实用的招：**SOP 内嵌执行脚手架**——在 SOP 开头直接写「读我之后第一件事，是把这几条坑写进工作记忆」。原仓库的 `ljqCtrl_sop.md` 就是这种写法（该文件已随裁剪移除），自己写 SOP 时可以照这个结构来。

## 批判：哪些是真进化，哪些只是提示词工程

**真进化（代码保证会发生的）**

- L1 索引每轮必现 → 新能力"一定会被看见"，这是唯一被代码保证的一环；
- L4 归档每 12 小时自动跑 → 会话不会无限堆积；
- `memory/` 文件系统会持续增长 → 能力确实在积累。

**提示词工程（靠模型自觉）**

- SOP 的生成、更新、压缩、淘汰 —— 全靠模型读规范 + 自己动笔；
- "失败三振出局""探测优先""只 patch 不改写"—— 全是文本；
- L1 ≤30 行 —— 代码只在 6000 字符时软提醒，且只在调工具时。

**结论**：ZicatAgent 的"自我进化"本质是 **"把学习行为的发生概率调到很高"**，而不是"用算法保证学习发生"。它赌的是：只要规范写得足够好、索引足够短、每轮都在眼前晃，一个足够强的模型就会自己完成知识管理。

这个赌注在强模型上成立（作者自己的实例能自举整个仓库），在弱模型上会迅速腐化（L1 越写越长、SOP 越写越水、重复条目堆积）。**自己造 Agent 时，这正是最该用代码加固的地方。**
