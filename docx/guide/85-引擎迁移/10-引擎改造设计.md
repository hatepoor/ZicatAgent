# 引擎改造设计（LangGraph + SQLite，本地单用户）

> 文档索引：[docs/README.md](../README.md) · 上游评估：[00-LangGraph迁移评估报告](00-LangGraph迁移评估报告.md)
>
> 适用前提：**本地单用户、不做多用户高并发**；模型统一 OpenAI 兼容接口；状态与记忆都用 SQLite。

## 0. 一句话架构

```
CLI / --task / --func / --reflect
        │
        ▼
engine/（LangGraph 控制面）
  StateGraph: prepare → agent ⇄ tools → finalize
  pre_model_hook / post_model_hook（重锚、裁剪、节拍、摘要）
        │                         │
        ├── SQLite checkpointer ──┤  temp/graph.db      （会话状态，高频写）
        └── SQLite 记忆库 ────────┘  memory/memory.db   （长期记忆，低频写、append-only）
```

## 1. 核心不变式（先钉死，后面所有设计都服从它）

| # | 不变式 | 说明 |
|---|---|---|
| I1 | **会话消息只追加** | 存储层的 `messages` 只 append；禁止删头、禁止替换既有消息、禁止"压缩旧消息" |
| I2 | **摘要也是新消息** | 需要压缩上下文时，生成一条新的 summary 消息追加到末尾，而不是重写旧消息 |
| I3 | **模型视图是投影** | 发给模型的 `[system] + [summary] + [最近 N 条]` 是运行时拼出来的临时列表，**不回写存储** |
| I4 | **记忆版本只追加** | `memory_versions` / `memory_events` 只 insert；`memory_items` 只更新"当前指针" |
| I5 | **状态与记忆分库** | checkpointer 高频写、记忆库低频写，物理隔离，互不影响备份与损坏半径 |
| I6 | **模型能改记忆，不能改状态** | 状态只由引擎写；记忆只能经记忆工具写，且必须留痕 |

> I1/I2 是用户明确要求：**新的消息内容永远追加在末尾，不允许破坏前缀**。

## 2. 会话状态（Checkpointer）

### 2.1 存储

| 项 | 取值 |
|---|---|
| 后端 | `SqliteSaver`（同步；CLI 单线程足够） |
| 文件 | `temp/graph.db`（`.gitignore`） |
| 参数 | `journal_mode=WAL`、`busy_timeout=5000`、`foreign_keys=ON` |
| 表 | `checkpoints` / `checkpoint_blobs` / `checkpoint_writes`（框架自带） |

```python
conn = sqlite3.connect("temp/graph.db", check_same_thread=False)
conn.execute("PRAGMA journal_mode=WAL")
conn.execute("PRAGMA busy_timeout=5000")
saver = SqliteSaver(conn); saver.setup()
```

### 2.2 State schema（追加式）

```python
class ZicatState(TypedDict):
    # 只追加：用 operator.add，不用 add_messages（后者允许按 id 替换）
    messages: Annotated[list[AnyMessage], operator.add]
    # 追加式摘要链（每条对应一段被折叠的历史）
    summaries: Annotated[list[str], operator.add]
    # 覆盖式：工作记忆（key_info、in_plan_mode、pending tips）
    working: dict
    turn: int
    exit_reason: str | None
    meta: dict
```

**为什么不用 `add_messages`**：它会按 message id 去重/替换，违反 I1。
流式 token 只在内存里累积，**一轮结束后整条提交一次**，不产生"半条消息更新"。

### 2.3 上下文构建器（I3 的落地）

```python
def build_model_view(state) -> list[BaseMessage]:
    msgs = state["messages"]
    budget = CONTEXT_CHAR_CAP            # 沿用 zicatAgent 的 context_win*3
    if total_chars(msgs) <= budget:
        return [system_msg()] + msgs
    # 超预算：从最老的开始折叠成一条新 summary（不删原消息）
    cut = split_point(msgs, keep_recent=N)
    folded = summarize(msgs[:cut])       # 可由模型生成，或规则压缩
    return [system_msg(), HumanMessage(summary_block(folded))] + msgs[cut:]
```

要点：
- 原消息**仍在 DB 里**，只是这次请求不带；
- 折叠结果缓存到 `state["summaries"]`（append），下次直接复用，避免重复摘要；
- 由此替代 zicatAgent 现在的"删头 + 把旧标签压成 `[...]`"（`llmcore.compress_history_tags` / `trim_messages_history`），后者在新架构里**退役**。

## 3. 图与编排

### 3.1 拓扑

```
START → prepare → agent
                    ├─ 有 tool_calls          → tools → agent
                    ├─ 需人工确认（ask_user）  → human(interrupt) → agent
                    └─ 结束 / 预算耗尽         → finalize → END
```

### 3.2 节点职责

| 节点 | 做什么 | 写哪些 State |
|---|---|---|
| `prepare` | 拼 system prompt（`sys_prompt` + 日期 + L1 视图），初始化 working | `messages`(system 不进 messages)、`meta` |
| `agent` | 组装模型视图 → 调模型（绑定工具）→ 追加 AI 消息 | `messages+1`、`turn+1` |
| `tools` | `ToolNode` 执行工具，结果作为 `ToolMessage` 追加 | `messages+k` |
| `human` | `interrupt()` 挂起，恢复后把用户答案追加为 `HumanMessage` | `messages+1` |
| `finalize` | 正常结束；预算耗尽时追加一条"交接总结"提示 | `exit_reason` |

### 3.3 两个 hook

**`pre_model_hook`（每次模型调用前，返回临时视图，不写 State）**

1. 工作记忆重锚：`working["key_info"]` → `### [WORKING MEMORY]` 临时消息；
2. 节拍纪律：按 `turn` 计算 17/41/175 三条提示；
3. L1 刷新：每 15 轮重新渲染 L1（从记忆库查询，见 §4）并替换 system 视图；
4. 上下文裁剪：调用 §2.3 的 `build_model_view`；
5. `<summary>` 缺失提醒。

**`post_model_hook`（模型返回后）**

1. 抽取 `<summary>` → `summaries` 追加；
2. 记录 token 用量（callback）；
3. 不修改任何既有消息（I1）。

### 3.4 预算

- 业务预算：`state["turn"] >= max_turns` → `finalize`（追加交接提示）；
- 框架预算：`recursion_limit = max_turns * 2 + 20`（一轮 ≈ agent + tools 两步）；
- 超限时同样走 `finalize`，不要裸抛异常。

### 3.5 中断与恢复

```python
from langgraph.types import interrupt, Command

def human_node(state):
    ans = interrupt({"question": state["working"]["_pending_question"],
                     "candidates": state["working"].get("_pending_candidates", [])})
    return {"messages": [HumanMessage(content=str(ans))]}
```

- `compile(checkpointer=saver)` + `thread_id` 是硬前提；
- CLI 收到 `__interrupt__` → 打印问题 → 读输入 → `Command(resume=答案)` 继续同一 thread；
- 未恢复的 thread 由清理任务按 TTL 回收。

### 3.6 中止

- 用户 Ctrl-C：`configurable["stop"]=True`，runner 在流消费循环检查并停止消费；
- 仍保留 zicatAgent 的"socket 强杀"补丁，仅用于挂死连接（LangGraph 不处理传输层）。

## 4. 记忆子系统（SQLite）

> 表结构与工具设计见 [20-记忆存储设计](20-记忆存储设计.md)。
> 本节只规定"引擎怎么用它"。

| 场景 | 调用 | 频率 |
|---|---|---|
| 任务开始拼 system prompt | `memory.render_l1()` | 每次任务 1 次 |
| 每 15 轮刷新 L1 | 同上 | 低频 |
| 模型查记忆 | 工具 `memory_search` / `memory_read` | 按需 |
| 模型写记忆 | 工具 `memory_write` / `memory_patch` / `memory_archive` | 任务结束 |

## 8. 已定决策与剩余问题

| # | 决策 | 结论 |
|---|---|---|
| D1 | 状态库 | SQLite `temp/graph.db`（本地单用户，已确认） |
| D2 | 记忆库 | SQLite `memory/memory.db`（已确认） |
| D3 | 记忆写入口 | **只允许 `memory_*` 工具**；`file_write/file_patch` 不得写 `memory/`（已确认） |
| D4 | 追加式边界 | 存储层只追加；模型视图可折叠（摘要替代早期消息，原文仍在库）（已确认） |
| D5 | L1 索引 | 完全动态生成，不存原文（已确认） |
| D6 | L3 技能 | 正文入库，执行时物化到 `temp/skills/`（已确认） |
| D7 | L4 归档 | 正文留盘，库中只存档案卡（已确认） |
| D8 | `--task` 长跑子进程 | **保留**，与图内子图分工（已确认） |
| D9 | 记忆导出 | `memory/export/*.md` 按需/每周导出并进 git（已确认） |

**分工（D8）**：

| 场景 | 引擎 |
|---|---|
| 一次性子任务、并行 fan-out | 图内子图 / `Send` |
| 多轮接力、中途干预、要活过 CLI 退出 | 进程级 `--task`（保留） |

### 9.4 与设计的偏差（已知）

1. **`ask_user` 的回答依赖 stdin**：interrupt 已支持跨进程恢复——非交互进程会保持挂起，新进程用 `/resume <thread>` 回答；但回答入口仍是 stdin（没有 GUI 输入框）。
2. **L1 每 15 轮刷新**：已通过 graph 的 `turn_end_callback` 恢复（第 15/30/… 轮注入 `<global_memory>`），任务开始时仍会注入一次。
3. **多模型 fallback 已随 legacy 删除**：当前单模型；需要多模型时用 `mixin_config` 的方案不再可用。
4. **`context_char_cap` 折叠是"保留最近 N 条"**：不再只插提示，折叠时会把最近 8 条 `summaries` 附进占位消息；仍未做 LLM 摘要。
5. **`P5` 已完成**：legacy 主体已删除，`--engine` 参数移除；历史评估见 [40-P5退役评估](40-P5退役评估.md)。
6. **写入口拦截**：`file_write`/`file_patch` 在 `ToolRuntime` 与 handler 两层都会拦截 `memory/`；但 `code_run` 里的脚本写入无法通用拦截（已知限制）。
7. **文件回退只覆盖 `file_write`/`file_patch`**：`code_run` 对文件的修改不进 worldline（无法可靠追踪任意脚本副作用）。
8. **`/rewind` 的对话回退与文件回退是两套编号**：对话用检查点 `[n]`，文件用 worldline 节点 id，需分别操作。
9. **usage 回调在流式渠道可能拿不到 token**：`UsageTracker` 优先，取不到时回退 `AIMessage.usage_metadata`（已实测 req/in/out 正确）。
