# 记忆存储设计（SQLite）

> 文档索引：[docs/README.md](../README.md) · 上层设计：[10-引擎改造设计](10-引擎改造设计.md)
>
> 目标：把现在散落在 `memory/*.md`、`*.py`、`memory/global_mem*.txt` 里的记忆，收进**单文件 SQLite**；
> 写入留版本、读取留痕迹、索引可动态渲染；**版本表只追加**。

## 0. 边界：哪些进库，哪些留在磁盘

| 内容 | 位置 | 理由 |
|---|---|---|
| L0 宪法（`assets/sys_prompt.txt`、`l1_structure.txt`） | 磁盘，只读 | 模型不得修改，是安全边界 |
| L1 索引 | **动态渲染**（不存原文） | 由库查询生成，避免索引与事实不一致 |
| L2 事实（原 `facts.txt`） | 库：`memory_items` | 需要版本与检索 |
| L3 SOP 与技能正文（`*_sop.md`、技能 `.py`） | 库：`memory_items` | 需要版本、检索、来源追踪 |
| **被代码 import 的运行时模块**（`memory/scripts/keychain.py`、`memory/memstore/l4_compress.py`、`memory/scripts/autonomous_helper.py`） | **磁盘** | 它们是程序模块，不是记忆内容 |
| L4 原始会话归档（`*.txt`、月 zip） | 磁盘 + 库里存元数据 | 体积大，二进制不适合入库 |
| 访问统计（`file_access_stats.json`） | 库：`memory_events` | 追加式事件天然适合 |
| 工作记忆（`key_info`） | 图状态 + `session_state` 表 | 会话级，不是知识 |

> 判断标准：**"给模型读的内容" 入库；"被 Python import 的代码" 留盘。**

## 1. 库文件与连接

| 项 | 取值 |
|---|---|
| 文件 | `memory/memory.db`（`.gitignore`；不进 git，二进制不做版本控制） |
| 连接 | 单写连接 + 读连接分离；`journal_mode=WAL`、`synchronous=NORMAL`、`busy_timeout=5000` |
| 并发 | 本地单用户，**单写者**；写操作用模块级锁串行化 |
| 备份 | `VACUUM INTO 'memory/backup/memory-YYYYMMDD.db'`，保留 7 日 + 4 周 |
| 迁移 | `PRAGMA user_version` 递增，启动时自动升级 |

## 2. 表结构（DDL）

```sql
PRAGMA journal_mode = WAL;
PRAGMA synchronous = NORMAL;
PRAGMA foreign_keys = ON;
PRAGMA busy_timeout = 5000;

-- 元信息
CREATE TABLE IF NOT EXISTS schema_meta (
  key   TEXT PRIMARY KEY,
  value TEXT NOT NULL
);

-- 记忆条目：只保存"当前有效版本"的指针与高频字段
CREATE TABLE IF NOT EXISTS memory_items (
  id             TEXT PRIMARY KEY,                    -- uuid4
  layer          TEXT NOT NULL CHECK (layer IN ('L1','L2','L3','L4')),
  kind           TEXT NOT NULL CHECK (kind IN ('index','fact','sop','script','archive','insight')),
  name           TEXT NOT NULL,                       -- 稳定标识：tmwebdriver_sop
  title          TEXT NOT NULL DEFAULT '',
  summary        TEXT NOT NULL DEFAULT '',            -- 供 L1 渲染的一句话
  body           TEXT NOT NULL DEFAULT '',             -- 正文（md 或 py 源码）
  tags           TEXT NOT NULL DEFAULT '[]',          -- JSON 数组
  meta           TEXT NOT NULL DEFAULT '{}',          -- JSON：来源、sha256、归档路径等
  status         TEXT NOT NULL DEFAULT 'draft'
                 CHECK (status IN ('draft','active','deprecated','archived')),
  priority       INTEGER NOT NULL DEFAULT 100,        -- L1 排序，越小越靠前
  verified       INTEGER NOT NULL DEFAULT 0,          -- No Execution, No Memory
  confidence     REAL    NOT NULL DEFAULT 0.0,
  created_at     TEXT NOT NULL,
  updated_at     TEXT NOT NULL,
  access_count   INTEGER NOT NULL DEFAULT 0,
  last_access_at TEXT,
  UNIQUE (layer, name)
);
CREATE INDEX IF NOT EXISTS idx_items_layer ON memory_items(layer, status, priority);
CREATE INDEX IF NOT EXISTS idx_items_updated ON memory_items(updated_at DESC);

-- 版本：append-only（insert only）
CREATE TABLE IF NOT EXISTS memory_versions (
  version_id INTEGER PRIMARY KEY AUTOINCREMENT,
  item_id    TEXT NOT NULL REFERENCES memory_items(id),
  title      TEXT NOT NULL,
  summary    TEXT NOT NULL,
  body       TEXT NOT NULL,
  status     TEXT NOT NULL,
  tags       TEXT NOT NULL,
  reason     TEXT NOT NULL,        -- create/patch/archive/restore/import
  actor      TEXT NOT NULL,        -- agent/user/system
  session_id TEXT,
  created_at TEXT NOT NULL
);
CREATE INDEX IF NOT EXISTS idx_versions_item ON memory_versions(item_id, version_id DESC);

-- 事件：append-only（读/写/注入/归档都留痕）
CREATE TABLE IF NOT EXISTS memory_events (
  event_id   INTEGER PRIMARY KEY AUTOINCREMENT,
  item_id    TEXT,
  event      TEXT NOT NULL,        -- create/read/patch/archive/inject/recall/prune
  actor      TEXT NOT NULL,
  session_id TEXT,
  detail     TEXT NOT NULL DEFAULT '{}',
  created_at TEXT NOT NULL
);
CREATE INDEX IF NOT EXISTS idx_events_item ON memory_events(item_id, created_at DESC);
CREATE INDEX IF NOT EXISTS idx_events_time ON memory_events(created_at);

-- 关系：索引→条目、替代、依赖
CREATE TABLE IF NOT EXISTS memory_links (
  from_id    TEXT NOT NULL REFERENCES memory_items(id),
  to_id      TEXT NOT NULL REFERENCES memory_items(id),
  rel        TEXT NOT NULL CHECK (rel IN ('indexes','supersedes','depends','related')),
  created_at TEXT NOT NULL,
  PRIMARY KEY (from_id, to_id, rel)
);

-- 会话级工作记忆（重启后可恢复；与图状态互为备份）
CREATE TABLE IF NOT EXISTS session_state (
  session_id TEXT PRIMARY KEY,
  working    TEXT NOT NULL DEFAULT '{}',
  plan_path  TEXT,
  updated_at TEXT NOT NULL
);

-- trigram：支持中文子串检索；不足 3 字的查询由 repository 回退 LIKE
CREATE VIRTUAL TABLE IF NOT EXISTS memory_fts USING fts5(
  name, title, summary, body,
  content='memory_items', content_rowid='rowid', tokenize='trigram'
);

-- 追加式强制：版本与事件禁止改删
CREATE TRIGGER IF NOT EXISTS trg_versions_no_update
BEFORE UPDATE ON memory_versions
BEGIN SELECT RAISE(ABORT, 'memory_versions is append-only'); END;

CREATE TRIGGER IF NOT EXISTS trg_versions_no_delete
BEFORE DELETE ON memory_versions
BEGIN SELECT RAISE(ABORT, 'memory_versions is append-only'); END;

CREATE TRIGGER IF NOT EXISTS trg_events_no_update
BEFORE UPDATE ON memory_events
BEGIN SELECT RAISE(ABORT, 'memory_events is append-only'); END;

CREATE TRIGGER IF NOT EXISTS trg_events_no_delete
BEFORE DELETE ON memory_events
BEGIN SELECT RAISE(ABORT, 'memory_events is append-only'); END;

-- FTS 与主表同步（items 的当前指针允许更新）
CREATE TRIGGER IF NOT EXISTS trg_items_fts_ins AFTER INSERT ON memory_items
BEGIN
  INSERT INTO memory_fts(rowid, name, title, summary, body)
  VALUES (new.rowid, new.name, new.title, new.summary, new.body);
END;

CREATE TRIGGER IF NOT EXISTS trg_items_fts_upd AFTER UPDATE ON memory_items
BEGIN
  INSERT INTO memory_fts(memory_fts, rowid, name, title, summary, body)
  VALUES ('delete', old.rowid, old.name, old.title, old.summary, old.body);
  INSERT INTO memory_fts(rowid, name, title, summary, body)
  VALUES (new.rowid, new.name, new.title, new.summary, new.body);
END;

CREATE TRIGGER IF NOT EXISTS trg_items_fts_del AFTER DELETE ON memory_items
BEGIN
  INSERT INTO memory_fts(memory_fts, rowid, name, title, summary, body)
  VALUES ('delete', old.rowid, old.name, old.title, old.summary, old.body);
END;
```

> `memory_items` 的更新只允许改"当前指针"字段与计数器；**正文历史必须经 `memory_versions` 追加**，
> 由工具层保证（更新 items 与插入 version 在同一事务）。

## 3. 写入路径（唯一入口）

```
模型 → memory_write / memory_patch / memory_archive（工具）
        └─ 事务：insert memory_versions → update memory_items 指针 → insert memory_events
用户 / 迁移脚本 → 同一套 repository 函数（memstore/repository.py）
```

约束：

| 规则 | 说明 |
|---|---|
| 名称唯一 | `(layer, name)` 唯一；改名 = 归档旧条目 + 新建 |
| 大小上限 | `body` ≤ 256 KB（超出让模型分段或落文件） |
| 不能写 L0 | 工具直接拒绝 layer='L0' |
| 不能直改版本 | 版本表有触发器保护 |
| 溯源 | 每次写入记 `actor` + `session_id` + `reason` |
| 验证门禁 | `kind='script'` 初始 `status='draft'`，执行成功后才允许 `active` |

## 4. 读取与索引

### 4.1 L1 动态渲染

L1 = **固定的规则块**（`l1_rules` 条目，规则是内容、不是索引）+ **动态索引**（查询生成）。

```sql
SELECT name, summary, kind, tags
FROM memory_items
WHERE layer IN ('L2','L3') AND status = 'active'
ORDER BY priority, updated_at DESC
LIMIT 40;
```

渲染成现有格式（保持模型习惯，降低改造成本）：

```
# [Global Memory Insight]
需要时 read L2 或 memory_search 查 L3

[RULES]                       ← l1_rules 条目原文
1. 搜索先行 ...

## 索引                        ← 以下由查询生成
[SKILL] tmwebdriver_sop — TMWebDriver SOP
[FACT]  global_mem — ...
```

- 总长截断到约 2,000 字符（现有 L1 是 23 行）；
- 每次渲染写 `memory_events(event='inject')`，便于统计"哪些条目从没被读"。

### 4.2 检索

```sql
-- 关键词（FTS5）
SELECT i.* FROM memory_fts f JOIN memory_items i ON i.rowid = f.rowid
WHERE memory_fts MATCH ? AND i.status = 'active'
ORDER BY rank LIMIT ?;
-- 过滤：layer / tags / 状态
```

降级：FTS5 不可用时用 `LIKE`（SQLite 内置，总能跑）。

### 4.3 读操作留痕

`memory_search` / `memory_read` 每次写一条 `memory_events(event='read')`，
同时 `access_count += 1`、`last_access_at = now`（与旧 `file_access_stats.json` 等价，但可查询）。

## 5. 工具接口（替换现有文件操作）

| 工具 | 参数 | 返回 | 说明 |
|---|---|---|---|
| `memory_search` | `query, layer?, tags?, limit?` | `[{name, summary, layer, kind, updated_at}]` | 只读 |
| `memory_read` | `name_or_id` | `{name, body, version, updated_at}` | 只读，留痕 |
| `memory_write` | `name, layer, kind, title, summary, body, tags?, verified?` | `{id, version}` | 新建；同名则报错 |
| `memory_patch` | `name, new_body, reason` | `{id, version}` | 追加新版本 |
| `memory_archive` | `name, reason` | `{ok}` | 状态转 archived |
| `memory_link` | `from, to, rel` | `{ok}` | 关系维护 |
| `memory_index` | — | `L1 文本` | 调试/自检用 |

> 实现状态（2026-10-23）：7 个工具已合并进 `assets/tools_schema.json`（唯一 schema 来源），
> 实现统一在 `memstore/tools.py`，`zicat.ZicatAgentHandler.do_memory_*` 转发 → legacy 与 graph
> 引擎都能调用；`memory/` 的 `file_write/file_patch` 在 graph 引擎被拦截（legacy 未拦）。
> `memory_search` 命中后对条目 `touch`（access_count + read 事件），`memory_read` 返回真实
> `version_count`。

与现有 SOP 的映射：
- `file_read('./memory/l1_fallback.txt')` → `memory_index()`
- `file_read('./memory/kb/xxx_sop.md')` → `memory_read('xxx_sop')`
- `file_patch(...)` 写 SOP → `memory_patch(...)`

## 6. 保留与清理

| 数据 | 策略 |
|---|---|
| `memory_items` | 永久；archived 保留但不出现在 L1 |
| `memory_versions` | **append-only，不删行**（触发器保护）；archived 条目也保留全部版本 |
| `memory_events` | **append-only，不删行**；访问留痕永久保留 |
| `memory_fts` | 由触发器维护，不单独清理 |
| 会话工作记忆 | 随 thread 清理（与 checkpointer 同 TTL） |
| 备份 | 每日 `VACUUM INTO` 到 `memory/backup/snapshots/`，保留最近 7 份 + 每周 1 份（4 周） |

> 原计划的"180 天事件清理 / 归档版本只留 20 个"与 append-only 冲突，**已取消**：
> 库内行永不删除，磁盘增长通过"备份轮转 + 必要时重建库"控制。
> 备份任务由 `reflect/scheduler.py` 每 24h 静默执行（`memstore.backup.run_backup`），
> 不消耗 LLM，也不删除任何记忆行。

## 6.1 文件与库的同步（SOP 改写场景）

修改 `memory/*.md` 后用 `python -m memstore.sync` 把差异写进库（每条 `memory_patch` 生成新版本），
同时刷新 `memory/backup/import_manifest.json` 的 sha256；`python -m memstore.verify` 应保持全绿。
`memstore.export` 用于生成可进 git 的确定性 md 快照。

## 7. 数据迁移映射（文件 → 库）

| 现有文件 | layer | kind | name | 说明 |
|---|---|---|---|---|

## 8. 已定决策与剩余问题

| # | 决策 | 结论 |
|---|---|---|
| D2 | 库文件位置 | `memory/memory.db`（gitignore，不进 git）（已确认） |
| D3 | 写入口 | **只允许 `memory_*` 工具**；`file_write/file_patch` 对 `memory/` 的写入被拦截（已确认） |
| D5 | L1 索引 | **完全动态生成**（固定规则块 `l1_rules` + 查询生成的索引）（已确认） |
| D6 | L3 脚本 | **正文入库**，执行时物化到 `temp/skills/<name>.py`（按内容哈希缓存）（已确认） |
| D7 | L4 归档 | **正文留盘**，库中只存档案卡（路径、轮数、摘要、thread_id、sha256）（已确认） |
| D9 | 导出 | `memory/export/*.md` 按需/每周导出并进 git；`memory.db` 不进（已确认） |
| D10 | FTS | trigram 分词 + 查询不足 3 字或 FTS 不可用时回退 LIKE（已实现） |

物化规则（D6 的落地）：

```python
def materialize(name: str) -> str:
    item = repo.get(name)                       # 取当前版本正文
    digest = sha256(item.body)[:16]
    path = f"temp/skills/{name}-{digest}.py"
    if not os.path.exists(path):
        os.makedirs("temp/skills", exist_ok=True)
        write(path, item.body)
        event(item.id, "materialize", path=path)
    return path
```

- 每次执行前校验 `sha256(body)`，内容一变路径就变，天然避免旧缓存；
- `temp/skills/` 可随时删除重建；
- 物化事件写入 `memory_events`，便于排查"跑的是哪一版"。

## 9. 导出（D9）

```bash
python -m memstore.export --out memory/export/
```

- 每个条目一个 md，带 front-matter：`name / layer / kind / status / version / updated_at / sha256`；
- 输出**确定性**：字段顺序固定，不含 `access_count`、`last_access_at` 等易变字段；
- `memory/export/` 进 git（可 diff、可回滚、可反向重建库）；`memory/memory.db` 不进；
- 触发时机：记忆改动后、迁移前后、每周一次——**不自动 commit**。
