# 迁移方案（文件式 → SQLite + LangGraph）

> 文档索引：[docs/README.md](../README.md)
> 目标设计：[10-引擎改造设计](10-引擎改造设计.md) · [20-记忆存储设计](20-记忆存储设计.md)
>
> 原则：**可回退、双读过渡、数据零丢失、旧文件在验收前不删**。

## 0. 迁移总览

```
P0 准备 ─► P1 建库+导入 ─► P2 引擎骨架 ─► P3 记忆切换 ─► P4 状态切换 ─► P5 退役清理
   │           │                │              │              │              │
  备份/分支    schema+迁移脚本    --engine graph  双读：DB优先     checkpointer  删旧模块
                                 + 对照测试        文件兜底        /threads
```

每个阶段结束都有**独立可验证的产物**和**回退动作**；上一阶段未通过不进下一阶段。

## 2. P1：建库与数据导入（1 天）

### 2.1 交付物

| 文件 | 作用 |
|---|---|
| `memstore/schema.sql` | 20 号文档里的完整 DDL |
| `memstore/db.py` | 连接、PRAGMA、`user_version` 升级 |
| `memstore/repository.py` | 唯一写入入口（事务封装） |
| `memstore/migrate.py` | 文件 → 库 的一次性导入（含 `--backup` 快照） |
| `memstore/verify.py` | sha256 比对、条目计数、L1 渲染、追加式触发器 |
| `memory/backup/` | 导入前的文件快照 |

### 2.2 导入映射

见 [20-记忆存储设计 §7](20-记忆存储设计.md)。要点：

1. 逐文件读取 → 计算 `sha256` → 写入 `memory_items` + `memory_versions`（`reason='import'`）；
2. 导入脚本**只读原文件，不改不删**；
3. `l1_fallback.txt` 不导入，其 `[RULES]` 段导入为 `l1_rules` 条目；
4. 运行时资产/模块跳过（`review_inline_prompt*.txt`、`compress_session.py`）；
5. L4 归档只登记元数据与路径；
6. `memory/backup/`、`memory/export/` 不参与扫描。

> **执行记录（2026-10-22）**：`python -m memstore.migrate --backup` 导入 26 条
> （L1 1 / L2 1 / L3 24），`python -m memstore.verify` 140 项全过；
> 快照 `memory/backup/import_20261022-175453/`，manifest `memory/backup/import_manifest.json`。
> 注意：**备份目录必须在扫描时排除**，否则二次运行会把快照当记忆重复导入。

### 2.3 验收

| 检查 | 通过标准 |
|---|---|
| 条目数量 | 与源文件一一对应，无遗漏 |
| 正文一致性 | 每个条目 `sha256(body)` == 源文件 `sha256` |
| 版本表 | 每个条目恰好 1 条 `import` 版本 |
| L1 渲染 | 与旧 `l1_fallback.txt` 语义一致（允许格式差异，列出 diff） |
| 只读性 | 原文件 mtime 未变 |

**回退**：删 `memory/memory.db` 即可，源文件没有任何修改。

## 3. P2：引擎骨架与对照测试（2–3 天）

### 3.1 交付物

| 文件 | 说明 |
|---|---|
| `engine/settings.py` | `ChatOpenAI` 参数、`graph_config` |
| `engine/llm.py` | 模型 + `with_fallbacks` |
| `engine/tools.py` | `tools_schema.json` → `StructuredTool`（内部调 `zicat.py`） |
| `engine/runtime.py` | handler/cwd/stop 的运行时注入 |
| `engine/state.py` | `ZicatState`（`messages` 用 `operator.add`） |
| `engine/hooks.py` | `pre_model_hook` / `post_model_hook` |
| `engine/graph.py` | `StateGraph` + `ToolNode` + 条件边 |
| `engine/checkpointer.py` | `SqliteSaver`（`temp/graph.db`） |
| `engine/runner.py` | 对外入口，翻译流式事件 |
| `agentmain.py` | `--engine {legacy,graph}` |

### 3.2 对照测试（必须做）

同一组任务分别用 legacy / graph 跑：

| 用例 | 观察指标 |
|---|---|
| 单轮问答 | 输出正确；token 误差 < 20% |
| 多轮工具（写文件→执行→读回） | 产物一致；轮数差 ≤ 1 |
| 长任务（>20 轮） | 上下文不超预算；无丢消息 |
| 工具报错 | 错误以 `ToolMessage` 回灌，模型能自愈 |

### 3.3 追加式校验

写一个测试：跑 30 轮后
- `state["messages"]` 长度只增不减；
- 所有历史消息内容与首次写入时一致（逐条 hash 比对）；
- 折叠只发生在 `build_model_view`，DB 中消息数不变。

**回退**：`--engine legacy`，graph 代码保留但不用。

## 4. P3：记忆读写切换（2 天）

### 4.1 双读策略

```
读：memory_source=db  → 查库
    失败 / 未命中   → 回退读文件（只读）
写：只写库（file_write 对 memory/ 的写入被工具层拦截并提示改用 memory_*）
```

### 4.2 步骤

1. 新增记忆工具（`memory_search/read/write/patch/archive/index`）；
2. 更新 `assets/tools_schema.json`（增加工具描述，保留旧的直到 P5）；
3. 更新 `memory/*_sop.md` 与 `assets/sys_prompt.txt` 中"读记忆"的指令：
   - `file_read('./memory/l1_fallback.txt')` → `memory_index()`
   - `file_read('./memory/kb/xxx_sop.md')` → `memory_read('xxx_sop')`
   *（注意：这些 SOP 本身也在库里，需要同时改库与文件，保证两处一致）*
4. L1 注入改为动态渲染，每 15 轮刷新一次；
5. 开启 `memory_events` 留痕，跑一周观察命中率。

### 4.3 验收

| 检查 | 通过标准 |
|---|---|
| 模型不再写 `memory/*.md` | 日志中无相关 `file_write/patch` 成功记录 |
| 索引一致性 | `memory_index()` 与库中 active 条目一致 |
| 版本可追溯 | 每次 patch 都有新 version，旧版本可读 |
| 追加式 | 对 versions/events 的 UPDATE/DELETE 被触发器拒绝 |

**回退**：`memory_source=file`，模型改回读文件；库里数据保留。

## 5. P4：状态切换（2 天）

### 5.1 步骤

1. checkpointer 接管会话状态，`llmcore.history` 在 graph 引擎下停用；
2. `/threads` 列表、`/resume <thread_id>` 恢复；
3. `/continue` 双读：先查 checkpointer，未命中再回退文本日志；
4. `ask_user` 改 `interrupt()`，CLI 增加"恢复"交互；
5. `/cost` 改读 `engine/callbacks`；
6. `/rewind`：图状态用 `get_state_history`，文件回退仍走 `core/rewind.py`。

### 5.2 验收

| 检查 | 通过标准 |
|---|---|
| 中断恢复 | 挂起后重启进程，`/resume` 能继续且历史完整 |
| 上下文预算 | 50 轮会话不超上限，DB < 5MB |
| 计数一致 | `/cost` 与旧统计误差 < 10% |
| 旧会话可读 | `/continue` 仍能列出旧文本日志会话（降级为只读） |

**回退**：`--engine legacy`，text 日志仍在，`/continue` 恢复旧路径。

## 8. 风险清单

| 风险 | 影响 | 对策 |
|---|---|---|
| 模型仍按旧 SOP 写文件 | 双真源、记忆不一致 | P3 同步改 SOP + 工具层拦截 + 文件只读提示 |
| 迁移漏条目 | 记忆丢失 | sha256 逐条比对，失败即中止 |
| DB 损坏 | 记忆不可用 | WAL + 每日 `VACUUM INTO` + 保留 7 日 |
| 版本/事件膨胀 | 文件变大 | 180 天事件清理 + 归档条目限版本数 |
| 追加式被破坏 | 历史被改写 | 触发器强制 + 代码审查 + 单测 |
| 上下文折叠丢关键信息 | 任务质量下降 | 折叠摘要保留原文引用；必要时提高预算 |
| LangGraph 版本漂移 | 升级破坏 | `pyproject` 锁版本 + 冒烟测试 |
| 双引擎并存期混乱 | 调试困难 | 明确 `--engine`，日志里打印引擎名 |
