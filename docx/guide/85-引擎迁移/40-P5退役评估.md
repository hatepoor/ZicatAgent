## 0. 结论

| 问题 | 结论 |
|---|---|
| 能直接删掉 legacy 引擎吗？ | **不能直接删**。`agent_loop.py` 里还有 4 个被 graph/memstore 复用的公共件（`StepOutcome`、`BaseHandler.dispatch`、`exhaust`、`json_default`）；`llmcore` 还被配置加载、插件、成本统计依赖。 |
| 退役主体是什么？ | `agent_runner_loop`（125 行）+ `llmcore` 的会话/协议层（约 900 行）+ `core/session_restore`（若放弃文本日志 `/continue`，1144 行）。 |
| 建议顺序 | ①② 抽公共件 → ③ 切默认引擎 → 烘跑 → ④ 处理 hooks/`/session.*` → ⑤ 删除并打 tag。 |
| 预计净减代码 | 约 1,200–2,600 行（取决于是否保留文本日志 `/continue` 与插件体系）。 |

## 1. 依赖审计（当前 HEAD）

| 模块 | 行数 | 谁在用 | 退役归属 |
|---|---|---|---|
| `agent_loop.py` | 125 | `agentmain`（`agent_runner_loop`）、`zicat`（`BaseHandler`/`StepOutcome`/`json_default`）、`engine/tools`（`StepOutcome`/`exhaust`）、`core/session_restore`（`get_pretty_json`） | **拆分**：公共件搬走，循环删除 |
| `llmcore.py` | 1212 | `agentmain`（`mykeys_store` + 6 个 Session 类）、`engine/settings`（`mykeys_store`）、`plugins/langfuse_tracing`（`_load_mykeys`）、`core/cost_tracker`（`install` 里 patch `_record_usage`） | **拆分**：抽配置加载器；会话/协议层随 legacy 删 |
| `core/session_restore.py` | 1144 | `core/cli`（`/continue` 文本日志、`format_list`） | **决策后定**（见 D11） |
| `core/cost_tracker.py` | 377 | `core/cli`（`/cost`） | 改写成 graph 版或随 legacy 删 |
| `core/rewind.py` | 1118 | `engine/rewind.py` | **保留**（可移到 `engine/` 名下） |
| `core/modes.py` | 485 | `core/cli` | **保留** |
| `core/plan_state.py` | 329 | `core/cli` | **保留** |
| `core/review.py` | 65 | `core/cli` | **保留** |
| `plugins/hooks.py` | 52 | **只有 `agent_loop` 触发**；graph 引擎完全不触发 | **决策后定**（见 D12） |
| `plugins/langfuse_tracing.py` | 129 | 依赖 hooks 事件 | 同上 |
| `zicat.py` | 618 | 两个引擎共用 | **保留**（只需改 `BaseHandler` 来源） |
| `engine/` | ~700 | graph 引擎 | 保留 |
| `memstore/` | ~1,100 | 记忆 | 保留 |

关键发现：

1. **`StepOutcome` 是耦合核心**：`zicat.BaseHandler`、`ZicatAgentHandler`、`engine.tools` 都依赖它，但它现在住在 `agent_loop` 里。抽出去之后 `agent_loop` 才可能删。
2. **`llmcore` 的职责被高估**：graph 引擎只用它加载 mykey（`mykeys_store`），其余 1,100 行（Claude/OpenAI Session、文本工具协议、历史裁剪、重试）都是 legacy 专用。
3. **`plugins/hooks` 在 graph 下是死代码**：只在 `agent-loop` 里 `_hook(...)`，graph 不调用；如果还要插件能力，必须先给 engine 加回调或明确废弃。
4. **`/session.*` 命令在 graph 下无效**：它改的是 `llmclient.backend` 的属性，graph 用 `ChatOpenAI`，不看这些字段——属于需要随 P5 一并清理的"假入口"。
5. **`--task` 的文件协议语义要复验**：graph 的下一个任务是同 thread 追加消息，而 legacy 是通过 `reply.txt` 续跑并携带 `_keyinfo`；删除 legacy 前必须确认 `--task` 的 `_keyinfo`/`_stop`/`_intervene` 行为在 graph 下等价。

## 5. 风险

| 风险 | 影响 | 缓解 |
|---|---|---|
| 隐藏耦合（hooks、cost patch、plugins） | 删除后运行时异常 | 先 grep + 单测 + 四模式回归 |
| `--task` 语义差异 | 长任务续跑行为变化 | 专项对照测试，必要时保留进程级旧实现 |
| 文本日志 `/continue` 用户 | 旧会话无法恢复 | 保留一个版本或提供导出/转换脚本 |
| 插件能力丢失 | Langfuse 追踪失效 | D12 明确：移植到 engine 回调或接受废弃 |
| 单点删除不可回滚 | 需要重写 | 分步提交 + tag + 备份 |
