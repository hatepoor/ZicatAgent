## 先想清楚：你继承的是"机制"还是"内容"

| 可继承 | 不建议继承 |
|---|---|
| 薄循环 + StepOutcome 三态 | 39 个中文 SOP（那是作者的环境经验） |
| 每步重锚 + 工作记忆 | 17/41/175 这组魔数（要按你的任务重新标定） |
| 字符预算裁剪 + 块折叠 | 纯文本协议客户端（除非你必须兼容杂牌端点） |
| 存在性索引（L1）替代 RAG | `memory/` 被 gitignore 的做法（必须改） |
| 9 原子工具 + code_run 兜底 | 无沙箱的代码执行（生产必须改） |
| `--reflect` 45 行自启动契约 | TMWebDriver 强依赖（除非你就要真实浏览器） |

## 最小可行内核（约 1200 行）

| 文件 | 作用 | 从原仓库拿什么 |
|---|---|---|
| `agent_loop.py` | 循环 + dispatch + StepOutcome | 几乎可直接复用（132 行） |
| `handler.py` | 你的 `do_*` 工具 | 借结构，工具按你的场景重写 |
| `llm.py` | 单条原生客户端 + trim | 只保留 `NativeOAISession` + `trim_messages_history` |
| `prompts/sys.md` | 角色 + 行动原则 | 重写（这是你的 Agent 的人格） |
| `prompts/work.md` | 重锚模板（history/key_info/cwd） | 借用结构 |
| `memory/META-SOP.md` | 记忆编辑规范 | 借公理与决策树，改成分层目录 |
| `memory/INSIGHT.md` | L1 索引 | 空白起步，跑几个任务让它长 |
| `tools/schema.json` | 工具描述 | 从 9 个里挑你需要的 |
| `scheduler.py` | 45 行 reflect 契约 | 可直接复用 |

**砍掉这些**：`frontends/`（上游 3.8 万行 UI，本仓库已裁剪）、`hub`、`conductor`、IM 机器人适配。这些是"产品化"的部分，不是"Agent 内核"。`MixinSession` 多模型路由本仓库保留了，它属于可用性而非产品化，是否砍掉看你是否需要多 key 故障转移。

## 建议改造的 6 个点（按优先级）

1. **记忆加版本控制**：`memory/` 独立 git 仓库，每次写入自动 commit。原版最大缺陷就是不可回滚。
2. **L1 加代码校验**：启动时检查行数、检查每个指向的 L3 文件是否存在、格式是否合法。坏索引直接拒绝启动并告警。
3. **记忆提纯改为自动 + 独立小模型**：任务结束时（不是靠模型自觉）用一次便宜的 LLM 调用，基于**原始日志**（不是被压缩的上下文）提炼候选记忆，再交给主模型 patch。这一步能解决"在残骸上回忆"的根本问题。
4. **代码执行加沙箱**：至少用子进程 + 工作目录限制 + 超时；生产环境用容器或 WASM。原版这里是裸奔。
5. **循环退出补收口**：`MAX_TURNS_EXCEEDED` 时注入一段"总结已完成/未完成/残余风险"的 prompt，让模型好好交接（借 `goal_mode.py:55-69` 的 `BUDGET_LIMIT_PROMPT`）。
6. **加一个"能力注册表"**：`memory/*.py` 里的脚本用 docstring + 统一入口暴露成"二级工具"，让模型不必每次 `code_run` 拼路径。原版完全靠文件名约定，脚本一多就会乱。

## 一个可落地的推进节奏

| 阶段 | 目标 | 验收标准 |
|---|---|---|
| 第 1 周 | 跑通最小内核：循环 + 3 个工具（code_run/file_read/file_write）+ 单模型 | 能完成"读一个网页并写总结到文件" |
| 第 2 周 | 加记忆：L1 索引 + 工作记忆 + 任务后沉淀 | 第二个同类任务明显更快/更少工具调用 |
| 第 3 周 | 加你的领域工具（2-3 个专用脚本）+ SOP | 领域任务一次成功率 > 60% |
| 第 4 周 | 加自启动（scheduler）+ 中断/恢复 | 无人值守跑一天不崩 |
| 第 5-6 周 | 补防护：沙箱、记忆版本、L1 校验、成本监控 | 故意写坏 L1 能自动拒绝；代码执行越界被拦 |

## 一句话总结这套框架最值得学的东西

> **它把"上下文"从"要记住什么"变成了"每一轮要重新告诉它什么"。**
>
> 一旦接受这个前提，记忆就可以外置成文件、历史就可以无情裁剪、模型就可以随时切换——整个系统的复杂度就从"如何维护一个巨大的状态"降到了"如何写好每一轮的提示词"。
