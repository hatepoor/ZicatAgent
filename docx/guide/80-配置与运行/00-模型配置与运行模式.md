# 模型配置与运行模式

> 文档索引：[docs/README.md](../README.md)

## 1. 模型配置：`mykey.py`

配置来自代码根目录的 `mykey.py`（已被 `.gitignore` 忽略，不会进版本库）。它会被 `mykey_loader.MyKeys` 按 mtime 热加载（`mykey_loader.py`），改动后无需重启即可生效。

最小配置只需要一个字典：

```python
native_oai_config = {
    'apibase': 'https://api.deepseek.com',
    'apikey': 'sk-xxx',
    'model': 'deepseek-flash',
}
```

按服务商协议选变量名，而不是按模型名：

| 变量名 | 走哪条路径 | 说明 |
|---|---|---|
| `native_oai_config` | `NativeOAISession` → `NativeToolClient` | 原生 function calling，OpenAI 兼容协议 |
| `*_config` 且名字不含 `native` | `ToolClient`（文本协议） | 把工具 schema 与对话拍平成一段文本 |

> 已统一 OpenAI 兼容接口；Claude 直连协议（`native_claude_config`）在 P5 中删除，
> Claude 模型请使用服务商的 OpenAI 兼容网关。

> 两条路径差异见 [10-核心循环/10-上下文与历史裁剪](../10-核心循环/10-上下文与历史裁剪.md)，**原生路径优于文本协议**。

### 常用可选项

| 键 | 作用 |
|---|---|
| `name` | 显示名；多个模型时用 `mixin_config` 按名引用 |
| `context_win` | 历史裁剪参考窗口（字符基数，非模型硬上限），默认 38000；含 deepseek 时默认 80000 |
| `max_tokens` | 最大输出 token |
| `stream` / `read_timeout` / `timeout` | 流式开关与超时 |
| `reasoning_effort` | 推理强度（依模型支持情况） |
| `omit_thinking` | 不把 thinking 写进会话历史 |
| `proxy` / `verify` | 代理与证书校验 |

多模型故障转移（`mixin_config`/`MixinSession`）随 legacy 引擎一并移除；当前每个进程使用 `mykey.py` 里第一个 OpenAI 兼容配置，切换模型请改配置或重启。

## 2. 运行入口

| 模式 | 命令 | 行为 |
|---|---|---|
| Web UI | `node ui/server.mjs` | 唯一用户前端；浏览器打开 `http://127.0.0.1:8765` |
| 持续协作 | `--task 名字 --input "..."` | 建 `temp/<名字>/`，从 `input.txt` 读任务，结果写 `output.txt`；用 `reply.txt` 继续下一轮，10 分钟无回复退出 |
| 纯函数 | `--func prompt.txt` | 读 prompt → 结果写 `prompt.out.txt` → 退出，适合并行 map |
| 无人值守 | `--reflect reflect/scheduler.py` | 加载监控脚本，轮询其 `check()` 决定何时自启动 |
| RPC | `python agentmain.py --rpc` | JSONL 协议，Web UI 与自动化脚本的内部接口（一般不用手敲） |

### 引擎

只有 **graph（LangGraph）** 一个引擎；legacy 手写循环已按 P5 删除，`--engine` 参数不再存在。

graph 引擎的产物：`session/graph.db`（会话检查点 + 会话/工作区/用量注册表）、`memory/memory.db`（记忆库）。
配置在 `mykey.py` 的可选 `graph_config` 字典里（`max_turns` / `context_char_cap` / `checkpointer` / `memory_db`）。

### Web UI（唯一前端）

```bash
cd ui; npm install; npm run build
cd ..; node ui/server.mjs      # → http://127.0.0.1:8765
```

- 显示层：流式回复、工具卡片、spinner、`/` 命令补全、`ask_user` 问答、Esc/按钮中断、用量与上下文统计；
- 后端：`ui/server.mjs` 启动 `python agentmain.py --rpc`，SSE 下行 + POST 上行；
- 前端结构：组合根 `ui/src/App.tsx` + 深模块 hooks（`useAgentSession`/`useComposer`）+ 原子组件；
- CLI（Python 交互式与 TypeScript CLI）已删除，只保留 Web UI。

### 斜杠命令

由 `core/commands.py` 分发：能直接完成的命令（`/help`、`/cost`、`/scheduler`、`/plan`、`/continue`）
当场输出结果，不消耗 LLM；模式类命令（`/review`、`/goal`、`/team`、`/autorun`、`/distill`、`/update`）
会把构造好的提示词作为任务投给 agent。

| 命令 | 作用 |
|---|---|
| `/help` | 显示命令列表 |
| `/review [范围]` | 在当前会话内做对抗式代码评审（默认审 `git diff`） |
| `/continue` | 列出 graph 会话（同 `/threads`；文本日志恢复已随 legacy 删除） |
| `/threads` / `/resume <thread_id>` | 列出 graph 会话 / 续跑该会话；若有挂起的 `ask_user`，当场回答并继续 |
| `/rewind [n]` | 列出对话检查点 / 下一任务从第 n 个检查点继续（graph） |
| `/rewind files` / `/rewind file <id>` | 查看文件回退点 / 回退文件（worldline） |
| `/memory index` / `/memory search <词>` | 查看 L1 索引 / 检索记忆库 |
| `/plan` / `/plan <plan.md>` | 查看计划进度 / 绑定计划文件 |
| `/cost` | 本进程 token 用量与上下文占用 |
| `/scheduler` | 列出 reflect 服务与定时任务 |
| `/scheduler start\|stop <名字>` / `refresh` | 启停 reflect 服务 / 清空进程扫描缓存 |
| `/goal` `/team` `/autorun` `/distill` `/update` | 进入对应工作流（注入 SOP 提示词） |
| `/exit` `/quit` | 退出 CLI |

实现：`agentmain._handle_slash_cmd` 先把命令交给 `core.commands.handle()`；返回 `None` 表示
已消费，返回字符串则作为该轮查询继续走正常任务流程。

> `/scheduler` 的"运行中/未运行"探测依赖 psutil：`pip install -e .[proc]`。
> 未安装时命令仍可用（列服务与定时任务），但无法判断运行状态、也无法 start/stop。

### 常用参数

| 参数 | 作用 |
|---|---|
| `--nobg` | 前台运行（默认 `--task/--func` 会后台拉起子进程） |
| `--nolog` | 不写 `temp/model_responses/` 日志 |
| `--no-user-tools` | 从 schema 中剔除 `ask_user` 与 `start_long_term_update` |
| `--verbose` | 打印每轮完整 prompt |
| `--llm_no N` | 选择第 N 个模型 |
| `--history file.json` | 预加载历史 |

### `--task` 模式的通信文件

主 agent 与子 agent 之间只靠文件通信（`agentmain.py:281-297`）：

| 文件 | 方向 | 含义 |
|---|---|---|
| `input.txt` | 主 → 子 | 初始任务 |
| `output.txt` / `outputN.txt` | 子 → 主 | 每轮结果，含 `[ROUND END]` |
| `reply.txt` | 主 → 子 | 继续下一轮的输入 |
| `_stop` | 主 → 子 | 当轮结束即停 |
| `_keyinfo` | 主 → 子 | 注入工作记忆 |
| `_intervene` | 主 → 子 | 追加一轮指令 |

## 3. 运行时产物

| 路径 | 内容 | 是否入库 |
|---|---|---|
| `temp/` | 工作区（Agent 的 `./`） | 否 |
| `temp/model_responses/model_responses_*.txt` | 每次请求/响应的原始日志，L4 归档与会话恢复的原料 | 否 |
| `memory/l1_fallback.txt` | L1 索引，每次任务注入 system prompt | 是（自进化资产） |
| `memory/*.md` / `*.py` | L3 技能库 | 是 |
| `sche_tasks/*.json` | 定时任务定义 | 否 |

> `memory/` 入库是本仓库与上游的关键差异之一，理由见 [70-二次开发/00-裁剪记录](../70-二次开发/00-裁剪记录.md)。

## 4. 排障入口

- 模型没生效：看启动时 `[Info] Load mykeys from ...` 的路径是否是你改的文件。
- 请求报错：`temp/model_responses/` 最新日志里有完整 prompt 与响应。
- 上下文异常：搜索日志里的 `[Debug] Current context` 与 `[Cut]/[Trimmed context]`。
- 浏览器工具失败：先确认 Chrome 扩展 `assets/tmwd_cdp_bridge/` 已加载，见 `memory/kb/web_setup_sop.md`。
