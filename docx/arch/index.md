## 指针规则

- **当前生效**：当前代码实际符合的架构版本，只有一个。
- **正在构建**：已决策、正在实现的草案版本，最多一个；没有则写"无"。
- 理解现有代码看生效版；新开发以草案版为目标。
- 草案落地后：草案 → 生效，旧生效 → 已归档，本页指针同步更新。

## 升级判定

命中任意一条才建议升级：

| 触发 | 例子 |
|------|------|
| 模块拓扑变化 | 新增/删除/合并模块，依赖方向反转 |
| 契约破坏性变更 | 调用方必须改代码才能继续工作 |
| 技术选型替换 | 框架、数据库、消息队列、部署形态 |
| 数据模型结构性重构 | 实体拆分/合并、关系模型改变 |
| 非功能基线变化 | 一致性模型、安全边界、多租户、性能等级 |

不算升级：新增字段、不破坏旧契约的新接口、模块内部重构、性能优化、bug 修复、单个功能新增。

## 维护规则

- 升级时整代复制 `arch/vN/` 为新目录，旧版转 `已归档` 并冻结只读。
- 版本内的小变化原地更新当前生效版，并在 `changelog.md` 记一条。
- 归档版本永不修改；发现历史文档有误，在当前版修正并注明。
- 每次修改 markdown，必须同步 `architecture.html`。
- 一个开发版本最多触发一次架构升级。
